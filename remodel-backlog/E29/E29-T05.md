# E29-T05 · Tailscale and network access

## What it is

Network access decides whether an environment can be reached from other devices at all. By default the desktop's bundled server listens only on loopback; turning on **Network access** binds it beyond loopback and advertises its LAN and tailnet addresses for pairing. **Tailscale HTTPS** goes further: it configures `tailscale serve` so the server is reachable at an HTTPS address such as `https://machine.tailnet.ts.net/` on the user's tailnet. HTTPS matters because the hosted web app (latest.app.e6code.com) can only talk to HTTPS endpoints, and features like live device video need HTTPS or localhost.

## When it is used

- Pairing a phone on the same Wi-Fi: turn on Network access, create a pairing link using the LAN address.
- Working from anywhere over Tailscale: enable Tailscale HTTPS on the desktop host, or run `e6 serve --tailscale-serve` / `e6 pair --tailscale` on a headless host.
- Using the hosted web app against a home server: needs the Tailscale HTTPS (or another HTTPS) endpoint.
- Turning remote access off again.

## How it works today

- **Entry points:** desktop Settings → Connections → This machine: Network access toggle (restarts), advertised endpoint list with a default, Tailscale HTTPS toggle with Set up / Disable alert dialogs; CLI `e6 serve --host <ip>`, `e6 serve --tailscale-serve [--tailscale-serve-port]`, `e6 pair --tailscale`, env `E6CODE_TAILSCALE_SERVE(_PORT)`; remove a mapping manually with `tailscale serve --https=443 off`. Desktop bridge `getServerExposureState`, `setServerExposureMode`, `setTailscaleServeEnabled`, `getAdvertisedEndpoints`.
- **Desktop** (report 08 F-19, owned by E30-T07): exposure modes `local-only` and `network-accessible`, persisted in desktop settings and restored at boot; endpoint discovery from network interfaces and Tailscale; Tailscale Serve port default 443.
- **Server** (`packages/tailscale/src/tailscale.ts`, 381 lines): `tailscale status --json` (1.5 s timeout) for MagicDNS name and tailnet addresses; configures and tears down `tailscale serve`; builds HTTPS base URLs for pairing; probes endpoints. Serve setup is parked until server activation so a failed trial update cannot tear down the running server's serve config.
- **Behaviour to preserve:**
  - Default is local-only; enabling network access is explicit and restarts the desktop server (the UI says so).
  - Advertised endpoints are hints; only the connecting device can prove a route works. Endpoint choice never silently falls back to loopback.
  - The mapping made by `e6 pair --tailscale` persists across restarts; disabling in Settings removes the route.
  - If port 443 is taken, a different serve port can be chosen.
  - Cookie-origin trust includes a Tailscale hostname only when it is this machine's own MagicDNS name (E29-T03).
  - Hosted web needs HTTPS; a hosted pairing link does not make an unreachable or HTTP backend reachable. Mobile IP entries default to HTTP; users add `https://` for HTTPS servers.
  - Missing `tailscale` binary or logged-out tailnet: the toggle explains why it is unavailable (exact copy not verified).
  - Browser clients see a read-only Network access row.
- **Surfaces:** desktop (controls), server and CLI (serve, pair), web (display).
- **Where the code lives:** desktop `apps/desktop/src/backend/DesktopServerExposure.ts`, `DesktopNetworkInterfaces.ts`, `tailscaleEndpointProvider.ts`; `packages/tailscale/src/tailscale.ts`; server `server.ts` (`tailscaleServeLayer`), `cli/pair.ts`, `auth/cookieOrigin.ts`, `environment/RemoteOpenTargets.ts`; web `ConnectionsSettings.tsx` (`NetworkAccessDescription` about line 1385, `AdvertisedEndpointListRow` 1303, `isTailscaleHttpsEndpoint` 509, `DEFAULT_TAILSCALE_SERVE_PORT` 185); docs `docs/user/remote-access.md` ("Pair over a LAN", "Tailscale HTTPS", "Hosted web app").

## Problems today

- The HTTPS requirement for the hosted app and device video is explained only in docs; the UI does not warn when the selected endpoint is HTTP.
- The browser read-only row tells users to "restart with a non-loopback host", which is CLI advice shown in a GUI.

## Remodel goals

- **Experience:** a reachability summary in words ("Only this computer", "Your network: 192.168.1.20", "Tailnet: https://studio.tailnet.ts.net") with each route's HTTPS status shown by icon and word; a warning before sharing an HTTP endpoint with a client that will need HTTPS.
- **Motion:** toggles apply instantly in the UI and show "Restarting…" until the server is back; no spinner without a label.
- **Remote:** the page must work when the client itself is connected through the route being changed (show what will drop before confirming).
