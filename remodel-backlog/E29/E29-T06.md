# E29-T06 · SSH environments

## What it is

The desktop app can add a remote machine over SSH with nothing but an SSH alias: E6 Code connects, installs or finds its server runtime on that host, starts (or reuses) a server there, mints a pairing credential remotely, forwards a local port to it and connects. Projects, provider credentials and agent work stay on the remote machine. If SSH needs a password, the desktop asks for it in a dialog with a countdown.

## When it is used

- A developer with a powerful Linux box or an Apple Silicon Mac reachable by SSH wants its agents and projects in their laptop's sidebar.
- A cloud VM without Tailscale or E6 Connect: SSH is the only route.
- Reconnecting after sleep or a network change, or after an app update.

## How it works today

- **Entry points:** desktop Settings → Connections → Add environment → SSH (host search over `~/.ssh/config` aliases, user, port, manual `user@host[:port]` parsed by `parseManualDesktopSshTarget`); the SSH password prompt dialog; server hidden CLI `e6 __ssh-helper pick-port|wait-ready|runtime-port` used by the remote bootstrap script.
- **Flow (desktop main process, not the renderer):** discover hosts from SSH config (Include handling, known_hosts); resolve with `ssh -G`; handle password/askpass prompts (main emits `onSshPasswordPrompt`, the web dialog answers with `resolveSshPasswordPrompt`); install or find the remote `e6` runner and Node (engine check script; downloads E6's server to `~/.e6/runtime` on first launch, which takes longer); launch or reuse a remote server; issue a pairing token remotely; forward a loopback port; wait for HTTP readiness; then fetch the descriptor, bootstrap a bearer session, fetch session state and issue WS tokens through the main process (bypassing browser CORS).
- **SSH Password Required dialog:** target description, password field, countdown in m:ss until the request expires, Cancel (becomes Dismiss when expired) and Submit.
- **Behaviour to preserve:**
  - Remote host must be Linux or Apple Silicon macOS with `curl` or `wget`, `tar`, `sha256sum` or `shasum`; provider CLIs must be on the PATH of a non-interactive login shell (`ssh host 'sh -lc "command -v claude codex"'`).
  - `serverKind` "managed" vs "external": disconnect or removal stops only a server the launcher started; an already-running server survives.
  - Reconnection restores the port forward before reopening the app transport.
  - After an app update, reconnect may need one retry (docs).
  - Password prompts expire; the password is passed to SSH only and never stored.
  - Windows uses a different ssh command name (`sshCommandForPlatform`).
  - Errors are formatted for people (`formatDesktopSshConnectionError`).
  - Antigravity's Google callback on an SSH host needs the remote sign-in flow (E27-T04).
- **Surfaces:** desktop (primary), server (helper), web (dialogs rendered inside desktop). Not on browser or mobile.
- **Where the code lives:** `packages/ssh/src/tunnel.ts` (1,787 lines), `command.ts`, `auth.ts`, `config.ts`, `errors.ts`; desktop `apps/desktop/src/ssh/DesktopSshEnvironment.ts`, `DesktopSshPasswordPrompts.ts` (470), `ipc/methods/sshEnvironment.ts`; server `apps/server/src/cli/sshHelper.ts`; web `components/desktop/SshPasswordPromptDialog.tsx` (221), `ConnectionsSettings.tsx` (SSH mode of Add Environment); docs `docs/user/remote-access.md` ("Desktop-managed SSH"), `docs/internals/remote.md`.

## Problems today

- Remote bootstrap scripts are JS source embedded as strings with `@@PLACEHOLDER@@` substitution; many failure modes, hard to read.
- First launch is slow (runtime download) with no stage-by-stage progress in the inventory (not verified).
- SSH is desktop-only, so a user who sets it up cannot see why it is missing in the browser client.

## Remodel goals

- **Experience:** the SSH flow shows real stages in words (Connecting, Checking host, Installing E6 runtime, Starting server, Forwarding, Connected) with the failing stage and its remedy when something goes wrong; the browser client shows SSH as "Available in the desktop app".
- **Motion:** stage list advances with `swap`; a stage completes with `checkDraw`; the password dialog uses the standard dialog preset and a `shake` on a rejected password.
- **Security:** never store or log SSH passwords; keep askpass handling in the main process.
