# E29-T04 · Saved environments and local environment

## What it is

A client can use several environments at once: its own local server plus any number of saved remote ones. **Saved environments** are the client's catalog of those connections: remote links (a host plus a pairing code or URL), SSH hosts (desktop launches and tunnels a server, E29-T06) and E6 Connect cloud environments (E29-T07). Each entry can be enabled or disabled, shows its connection phase, can be removed, and can be updated when its server version lags behind the client. The desktop app can also turn its own **local environment** off and run as a remote-only client. Each environment has a machine icon the user can choose.

## When it is used

- Adding a second computer (a desktop at home, a cloud VM) so its projects appear in the sidebar beside local ones.
- Temporarily disabling a slow or offline machine without forgetting it.
- A remote server shows "version mismatch"; the user runs "Update server" from the client.
- A laptop used only to drive a powerful desktop turns Local environment off.
- Picking a "Mac mini" or "server" icon so machines are easy to tell apart in menus.

## How it works today

- **Entry points:** Settings → Connections → Environments (Add environment, row switch, row menu: copy trace id, remove; Update servers); welcome wizard step 1; mobile Settings → Environments and Connections sheet (E34-T03); desktop Settings → Connections → Local environment; machine icon menu.
- **Add a remote link:** host + pairing code, or paste a full pairing URL (direct `/pair#token=` or hosted pairing URL, parsed by `parsePairingUrlFields`); the client redeems the credential and stores a bearer/DPoP session for that environment.
- **Rows:** name and icon, connection phase with words (connecting, connected, offline, error with trace id), enable switch, remove (with confirmation; for SSH, removal stops a server E6 launched, E29-T06), version mismatch with "Update server" (optionally also update the desktop app and continue running threads across the restart, E38-T03), cloud rows from E6 Connect.
- **Storage:** web keeps the catalog in client storage (`client-runtime` connection registry; hosted web in the browser); desktop persists it in the main process (`DesktopConnectionCatalogStore.ts`, 518 lines; `DesktopSavedEnvironments.ts`) with secrets encrypted by Electron `safeStorage` or `@napi-rs/keyring` (Linux password-store selection, E30-T08); mobile in secure store with migrations of old formats.
- **Local environment off** (desktop setting `localEnvironmentEnabled`): relaunches the app; on start the main process skips port selection, exposure and primary and WSL backends; the renderer sees `getLocalEnvironmentEnabled() === false`, skips primary auth and connects only saved environments. Nothing local is deleted; turning it back on restores previous local settings.
- **Machine icon:** glyphs mac mini, studio, laptop, desktop, server, cloud, VM; stored server-side as `environmentIcon`; the server detects a default from `platform.machine` (E29-T10).
- **Behaviour to preserve:**
  - Multi-environment: projects and threads belong to one environment; saved connections are local to a client profile; server identity is independent of the route (`docs/internals/remote.md`).
  - Disabled entries keep their credentials and reconnect when re-enabled.
  - Clients use advertised capabilities of each server and handle their absence (servers can be several releases behind).
  - Hosted web stores its catalog in the browser and connects directly; it cannot reach plain-HTTP LAN servers from an HTTPS page.
  - Mobile: IP entered without a scheme uses HTTP; LAN cleartext is allowed by the app's network config.
  - Credentials are never shown again after pairing; secrets at rest are encrypted on desktop and mobile.
  - Remote-only desktop: no local agents, terminals or WSL; other devices cannot connect to this computer.
- **Surfaces:** web, desktop, mobile, server (icon setting, version, update RPCs).
- **Where the code lives:** web `components/settings/ConnectionsSettings.tsx` (`SavedBackendListRow` about line 1481, `savedBackendStatus` 1444), `EnvironmentRow.tsx`, `EnvironmentIconPicker.tsx`, `LocalEnvironmentSetting.tsx`, `apps/web/src/localEnvironment.ts`, `apps/web/src/connection/`, `state/environments`; `packages/client-runtime/src/connection/*` (registry, resolver), `state/connections.ts`; desktop `apps/desktop/src/app/DesktopConnectionCatalogStore.ts`, `settings/DesktopSavedEnvironments.ts`, `electron/ElectronSafeStorage.ts`, `settings/DesktopAppSettings.ts`; mobile `src/connection/*`.

## Problems today

- Three storage implementations (browser, Electron main, mobile secure store) of one catalog concept.
- Row states (phase, version, update, cloud) are computed in the 3,779-line connections file.
- A disconnected environment's rows and its projects' sidebar entries can disagree about state (not verified).

## Remodel goals

- **Experience:** each environment is a card with icon, name, reach ("LAN · 12 ms", "E6 Connect", "SSH via studio") in words, one status mark and one action when something is wrong. The same view model drives the sidebar environment header and mobile.
- **Motion:** connection phase swaps with `iconSwap`; adding an environment inserts the row with `reveal`; enable/disable applies instantly and shows "Connecting…" text until the socket opens.
- **Performance:** one subscription per environment row; reconnect storms after network change are coalesced.
