# E29-T09 · GitHub sharing between environments

## What it is

GitHub sharing lets one environment borrow another environment's GitHub sign-in for pull request work. If the laptop's server is signed in to GitHub (`gh auth login`) but a cloud VM is not, the client can route the VM's pull request reads, and optionally actions, through the laptop. Each saved environment gets a permission: Off (default), Read PRs, or Read and act. Trust is given to a specific saved connection, not to whatever environment id a server claims.

## When it is used

- A user's cloud or SSH machine has no GitHub credentials, but they still want the Pull requests page and PR review details for projects there.
- A user wants a remote machine to merge or comment through their main machine's GitHub account (Read and act).

## How it works today

- **Entry points:** Settings → Connections → GitHub sharing (web/desktop); mobile Settings → Environments → GitHub routing.
- **Storage:** per client, a list of `{ environmentId, connectionKey, permission }` with permission `off | read | read-write`. The connection key is derived from the saved endpoint (relay target id; SSH alias, hostname, user and port; or HTTP/WS base URLs).
- **Behaviour to preserve (security):**
  - Off by default for every environment.
  - Trust belongs to the saved endpoint, never to an environment id advertised by a server alone; if the endpoint changes, the permission no longer applies.
  - Routing is only to another connected environment signed in to the same GitHub account.
  - Verified-credential fallback lasts ten minutes; uncertain actions are never retried automatically.
  - Read PRs never performs writes; Read and act is required for actions.
- **Surfaces:** web, desktop, mobile (client-side setting); server PR service performs the routed calls (E24-T13).
- **Where the code lives:** `apps/web/src/components/settings/GitHubRoutingSettings.tsx` (127 lines) and its test; `packages/client-runtime/src/connection/githubRoutingPermissions.ts`, `state/pullRequestRouting.ts`, `connection/resolver.ts`, `registry.ts`; mobile `GitHubRoutingSettings.tsx`; docs `docs/user/source-control.md` ("GitHub sharing", "Cross-environment GitHub routing").
