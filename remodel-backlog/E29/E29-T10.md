# E29-T10 · Environment identity and machine descriptor

## What it is

Every environment has a stable identity that clients rely on: an environment id that survives restarts and address changes, a human label (the machine's name), a machine description (chassis type, vendor, product, used to pick a default machine icon) and the hostnames other devices can use to open its files in an editor remotely (SSH, MagicDNS, mDNS names). Every client reads these through the server descriptor and config. No screen of its own.

## When it is used

On every connection: the sidebar environment header, scope menus, saved environment rows, machine icons, "open in editor" deep links from a remote client, and matching a saved connection to the server it reaches.

## How it works today

- **Entry points:** `getDescriptor` in server config, `serverGetConfig`, `shellOpenInEditor`; `/.well-known/e6/environment`.
- **Identity:** a persisted environment id with atomic publication and a recovery file for repairing an empty id file, so concurrent or delayed initialisers choose the same winner.
- **Label:** macOS ComputerName, Linux pretty hostname, else the working directory.
- **Machine:** chassis type, vendor, product name; the server detects `platform.machine` and the user may override with the `environmentIcon` server setting (mac mini, studio, laptop, desktop, server, cloud, VM; E29-T04).
- **Remote open targets:** SSH, MagicDNS and mDNS hostnames for remote editor deep links.
- **Behaviour to preserve:**
  - The id never changes for an environment and is independent of the route used to reach it.
  - The recovery file must not be cleaned up as a temporary file; doing so can change the identity under a running server.
  - Projects and threads belong to one environment id; a repository identity correlates clones across environments but never routes work.
  - Older clients must still decode the descriptor (new fields optional).
- **Surfaces:** server; all clients consume.
- **Where the code lives:** `apps/server/src/environment/ServerEnvironment.ts`, `ServerEnvironmentLabel.ts`, `ServerEnvironmentMachine.ts`, `RemoteOpenTargets.ts`; contracts `packages/contracts/src/environment.ts`; docs `docs/internals/remote.md` ("Identity is independent of the route").

## Problems today

- None reported beyond the recovery-file trap; the area is small and stable.

## Remodel goals

- No behaviour change; v2 clients present identity consistently (icon, label, reach) through one shared view model used by sidebar, settings and mobile.

## Done when

- [ ] Identity, label, machine and remote targets are unchanged on the wire; a contract compatibility test covers the descriptor.
- [ ] The same environment reached over local, LAN, tailnet and relay shows one identity in the client (test or manual check).
- [ ] A server test covers concurrent initialisation with an empty id file.
