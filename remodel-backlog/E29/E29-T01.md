# E29-T01 · Connections settings and dialogs

## What it is

Settings → Connections is the control room for remote access. It answers two questions on one page: how other devices can reach this machine (network access, advertised addresses, Tailscale HTTPS, WSL, E6 Connect, and the pairing links and client sessions that have been authorised) and which other environments this client uses (saved remote links, SSH hosts and E6 Connect cloud environments, with load balancing and GitHub sharing between them). An **environment** is one running E6 server and the machine and state it owns; a **client** is the web, desktop or mobile app talking to it. This task is the page and its dialogs; the capabilities behind each section have their own tasks (E29-T02 to T10).

## When it is used

- Turning on Network access so a phone on the same Wi-Fi can pair, then creating a pairing link and showing its QR code.
- Adding a second machine (a Mac mini, a cloud VM) by pasting its pairing URL or by SSH.
- Seeing which phones and browsers have access, and revoking a lost device.
- Running the desktop app as a remote-only client (Local environment off).
- Updating a remote server whose version lags behind the client.

## How it works today

- **Entry points:** settings nav "Connections" (badge with the saved-environment count; device-only page, no scope breadcrumb); settings search anchors; welcome wizard step "Connect your computers" (E11-T01); sidebar environment status; update notices ("Update server"); CLI equivalents `e6 pair`, `e6 auth …`, `e6 connect …` (E38-T01).
- **Sections, in order (desktop or a manageable backend):**
  1. **This machine:** environment icon menu (E29-T10, F-22), Local environment on/off (desktop; restarts the app), Version with update action, Network access toggle (desktop; restarts the server/app), advertised endpoint list with a default choice, Tailscale HTTPS toggle (E29-T05), WSL backend and WSL-only toggles plus distro (Windows, E30-T06), E6 Connect (managed tunnel, E29-T07), Publish agent activity (mobile notifications, E35-T01).
  2. **Authorized clients** (folded; only when the environment is remotely reachable and the session holds `access:read`): pairing links and client sessions with scope summaries, Create pairing link, revoke one, revoke others (E29-T02).
  3. **Environments:** saved environments with enable switch, connection status, copy trace id, remove; E6 Connect cloud environments; Add environment; Update servers (E29-T04, T06, T07).
  4. **Load balancing** (only with two or more enabled environments, E29-T08) and **GitHub sharing** (E29-T09).
- **Dialogs:** Add Environment (mode card: Remote link = host + pairing code or a pasted pairing URL; SSH = desktop only, host search over SSH config, user, port, with animated height); Create pairing link (label + scope checklist, at least one scope); pairing link row/popup with QR code, endpoint selector, copy token or URL, revoke; Set up / Disable Tailscale HTTPS alert dialogs; Revoke other clients and Remove backend confirmations.
- **Browser client differences:** "Network access" is a read-only row ("Only this machine can connect. Restart with a non-loopback host for remote pairing."); an "Administrative access" row appears; desktop-only rows are absent.
- **Behaviour to preserve (UI):**
  - Every section has loading, per-action error, empty and disconnected states; errors are shown per action, not as a page failure.
  - E6 Connect rows are hidden entirely when the build has no public cloud config.
  - Restart-requiring toggles (Network access, Local environment) say so before acting.
  - Sections the session lacks scopes for are hidden or read-only, never shown and then failing.
  - Pairing URLs are shown only in the client that created them, only while the page stays open (E29-T02).
- **Behaviour to preserve (security):** the page must not widen what the server enforces. Creating a link needs `access:write` plus every delegated scope; reading the list needs `access:read`; the list never contains recoverable secrets; relay changes need `relay:write`. Endpoint selection must never silently fall back to a loopback address when a shareable one is unavailable (docs/internals/remote.md).
- **Surfaces:** web and desktop share the page (desktop adds rows through `desktopBridge`); mobile has its own Settings → Environments (E34-T03); server endpoints behind each section.
- **Where the code lives:** `apps/web/src/components/settings/ConnectionsSettings.tsx` (3,779 lines; `ConnectionsSettings` at line 1823; dialogs about 580-1230 and 3396-3669), `ConnectionsSettings.logic.ts`, `EnvironmentRow.tsx`, `LocalEnvironmentSetting.tsx`, `LoadBalancingSettings.tsx`, `GitHubRoutingSettings.tsx`, `EnvironmentIconPicker.tsx`, `FoldedSettingsSection.tsx`, `apps/web/src/pairingUrls.ts`, `hostedPairing.ts`, `components/cloud/*`.

## Problems today

- The single largest settings file; parse/format helpers, QR rendering, endpoint selection and four dialogs are inline.
- The page mixes "how others reach me" with "what I connect to", and many rows are conditional on platform, scope and cloud config, so the page looks very different per client and is hard to test.
- The Authorized clients section disappears entirely on a loopback server, which hides the concept from users who have not enabled network access yet.

## Remodel goals

- **Experience:** two clear halves, "This machine" (reachability and who has access) and "Other environments", each with a one-line reach summary in words ("Reachable on your LAN and tailnet · 3 clients"). Show what a toggle will do and what restarts before it happens. The pairing QR is the only key light when a link is being shared.
- **Motion:** dialogs use the standard dialog preset; Add Environment mode switch uses `sideBySide` and the `layout` preset instead of animated height; status changes use `iconSwap`. Toggling a row applies instantly in the UI and shows a pending word until the server confirms.
- **Structure:** each section is its own module consuming `client-runtime` services; no auth logic in components.
- **Performance:** the page code is lazy-loaded; QR rendering only loads when a QR is shown.
