# E35-T02 · Subscription usage widgets

## What it is

Home-screen widgets that show how much of the user's Codex and Claude subscription quota is left (the session window and the weekly window) without opening the app. On iOS the "Subscription usage" widget comes in small, medium, large, extra-large and lock-screen rectangular sizes, and the user can choose per provider whether it shows the session window, the weekly window or both ("Edit Widget"). On Android a home-screen widget shows the same data. Tapping a widget opens Settings > Usage on the Limits tab.

## When it is used

- Glancing at remaining quota before starting a heavy task, or deciding which provider to use next.
- Watching a weekly limit near the end of the week.
- Checking reset times without opening the app.

## Current screen

No screenshot: mobile screens could not be captured in this environment (no simulator). Capture with `pnpm screenshots:mobile` on a Mac; see `docs/operations/mobile-app-store-screenshots.md`. (The harness does not capture home-screen widgets; capture them by hand on a device.)

Layout in words: each provider is a row with its name, a detail line, and per window a label ("Session", "Weekly"), a progress bar of remaining quota, the percentage, and the reset time. Larger sizes show more windows and providers; the lock-screen rectangular size shows the most important line. Status colours (primary, warning, success, error) are generated from the stock palette into the widget source. Each Android row has a spoken description "<provider>. <window>. <percent>. <reset>. <detail>".

## How it works today

- **Entry points:** the OS widget gallery (iOS "Subscription usage", Android widget picker); iOS "Edit Widget" with the options Both / Session / Weekly per provider (Codex, Claude); widget tap opens `settings/usage?tab=limits`.
- **Behaviour to preserve:**
  - `SubscriptionUsageCoordinator`, a null-rendering component mounted at the app root, builds a snapshot from the shared usage-limit presentations (`@e6tools/shared/usageLimits`: pooled accounts and windows) and publishes it to the platform widget whenever it changes; its atom compares snapshots so busy thread updates do not republish.
  - Data is refreshed only while the app runs: probes every 5 minutes for connected environments, bounded across reconnects and foreground transitions (`createWidgetRefresher`).
  - Snapshots expire after 15 minutes; the widget shows them as stale rather than as current (background refresh would need a separate authenticated transport while the app is suspended).
  - Per-provider period configuration on iOS ("auto" means both).
  - Accessibility labels per row on both platforms.
- **Surfaces:** mobile only. The data is the same as the Limits tab (E34-T07) and web's Limits page (E28-T02). Server: usage tracking and limit sources (`07:F-48`).
- **Platform differences:** implemented twice. iOS: a SwiftUI widget written in TypeScript with `@expo/ui/swift-ui` and `expo-widgets` (`src/widgets/SubscriptionUsage.tsx`, configured in `app.config.ts` `widgetsPlugin`). Android: a native Kotlin module `modules/e6-subscription-widget` with a RemoteViews `SubscriptionUsageWidget.kt`; publishing goes through `publishSubscriptionUsage.{ios,android}.ts`. The widget logo asset comes from a config plugin.
- **Where the code lives:** `apps/mobile/src/widgets/SubscriptionUsage.tsx` (279), `SubscriptionUsageCoordinator.tsx`, `subscriptionUsageSnapshot.ts` (134), `useSubscriptionUsage.ts`, `publishSubscriptionUsage{,.ios,.android}.ts`, `apps/mobile/modules/e6-subscription-widget/android/.../SubscriptionUsageWidget.kt` (163), `app.config.ts` (widgets plugin), `scripts/generate-uniwind-themes.mts` (widget status colours).

## Problems today

- Data goes stale 15 minutes after the app was last open; the widget cannot refresh itself.
- Only Codex and Claude are configurable; other providers that report limits are not covered (not verified whether they appear).
- Two implementations (SwiftUI and RemoteViews) must keep layout and wording aligned.

## Remodel goals

- **Experience:** a widget that reads in one glance: remaining quota as a bar plus words, reset time, and an honest "Updated 20 min ago" when stale. Same status vocabulary and role colours as the app.
- **Performance:** publishing stays off the hot path (root leaf component, equality-checked snapshots); no extra network calls just for the widget while the app is in the foreground.
