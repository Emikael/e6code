# E15-T07 · Codex feedback submission

## What it is

On Codex threads, typing `/feedback` uploads the conversation and Codex's logs to OpenAI and returns a thread ID the user can quote to OpenAI support. A banner above the composer shows the upload in progress, then "sent" with a Copy ID action, or a failure.

## When it is used

- Reporting a Codex bug or bad behaviour to OpenAI with the evidence attached.

## Current screen

No screenshot: the capture environment did not run a Codex feedback upload. The notice is a composer banner with three states: uploading, sent (thread ID with Copy ID), failed.

## How it works today

- **Entry points:** `/feedback` in a Codex thread (provider command from the `/` menu, E14-T02).
- **Behaviour to preserve:**
  - Only Codex supports it (adapter `uploadFeedback`; E37-T11 matrix: Codex yes, all others no).
  - The notice state comes from `codexFeedbackNotice` in the client-runtime thread state and renders in the banner stack (E14-T09) with progress, sent with Copy ID, or failed.
  - The upload sends conversation and logs off the machine to OpenAI.
- **Surfaces:** web and desktop; mobile not verified. Server: Codex adapter.
- **Where the code lives:** `apps/web/src/components/chat/ComposerFeedback.tsx` (49), `@e6tools/client-runtime/state/threads` (`codexFeedbackNotice`), Codex adapter (`apps/server/src/provider/Layers/CodexAdapter.ts`).

## Problems today

- Nothing tells the user before upload that logs leave the machine (not verified whether Codex itself prompts).

## Remodel goals

- **Experience:** a one-line confirmation before upload stating what is sent and to whom; the sent state keeps the ID copyable until dismissed. Copy uses the `iconSwap` copy-to-check moment (§3.9).

## Done when

- [ ] `/feedback` works on Codex and is absent from other providers' menus, driven by the capability descriptor.
- [ ] Uploading, sent (Copy ID) and failed states in the v2 banner stack, dark and light.
- [ ] Privacy note shown before upload, or a recorded decision not to.
