# E15-T06 · Jev routing (System One pre-router)

## What it is

Jev routing (called "System One" in the code) is an optional, off-by-default pre-router on the environment server. When enabled with a Jev API key, each user turn is first classified by TypeSafe's hosted Jev decision API. Exact greetings and simple lookups are answered on the server with a template, without calling the provider at all; straightforward questions are sent to the provider with trimmed context; everything else goes to the provider as usual. Any failure falls back to the provider. Turn content leaves the machine when this is on.

## When it is used

- Users who want to save provider usage on trivial turns ("thanks", "hi").
- Users on metered plans who want trimmed context for simple questions.

## How it works today

- **Entry points:** Settings → General (per environment) → "Jev routing" switch and "Jev API key" (write-only, stored in the server's secret store); the turn dispatch path in `ProviderCommandReactor.ts` (`routeSystemOneTurn`); Usage page section.
- **Behaviour to preserve:**
  - Pre-checks skip Jev: disabled, empty text, attachments present, and a key-material tripwire (turns that look like they contain an API key or private key, in the message or the previous exchange).
  - For other turns the message plus the previous message and reply in that thread are sent to Jev. Confidence thresholds come from settings (`confidencePolicy.ts`); policy decides between deterministic templated answer (`deterministicResponder.ts`), fast path (`fastPath.ts`) or full provider turn.
  - Fail-open on any error or timeout; an LRU of past answers; usage tracker records calls and outcomes, published as receipts; counters reset when the server restarts. Cost is $0.042 per million input tokens, metered per call.
  - Settings description warns: "Turn content leaves the machine; the API key stays on this server."
  - How a locally answered turn appears in the timeline (as a normal assistant message, or marked) is not verified.
- **Surfaces:** server (router), web and desktop (setting and Usage section). Mobile: Usage may show the section (not verified); no setting on mobile (not verified).
- **Where the code lives:** `apps/server/src/systemOne/SystemOneRouter.ts` (233), `JevEngine.ts` (323), `stateBuilder.ts`, `confidencePolicy.ts`, `deterministicResponder.ts`, `fastPath.ts`, `systemOneUsageTracker.ts`; `orchestration/Layers/ProviderCommandReactor.ts`; settings `SystemOneSettings` in contracts; web `components/settings/SettingsPanels.tsx:3088-3150`, `components/usage/UsagePage.tsx:589`; docs `docs/user/usage.md` ("Route turns through Jev").

## Problems today

- Not owned by any area in the inventory (report 06 flagged it); it depends on a third-party SDK (`@typesafe-ai/sdk`).
- Users cannot see in a thread which turns Jev answered (not verified that any marker exists).
- Counters are in memory and reset on restart.

## Remodel goals

- **Experience:** if kept, a turn answered without the provider carries a small, honest marker ("Answered by Jev routing") so the user is never misled about who replied; the setting keeps its privacy warning next to the switch.
- **Performance:** classification must not add latency to the command acknowledgement budget (≤ 10 ms p95); it runs after the turn is accepted.
