# E15-T02 · Effort and model traits

## What it is

Each model has options ("traits") that change how it works: reasoning effort (for example Low to Ultrathink, or Fast / Balanced / Deep), fast mode, context window size (200k or 1M), agent selection, and thinking toggles. The traits menu in the composer exposes the options the selected model declares, with a segmented effort control shown inline when there is room. Permission mode and plan mode also appear in this menu today but are covered by E15-T08.

## When it is used

- Raising effort for a hard bug, lowering it for a quick edit.
- Switching to the 1M context window for a large codebase.
- Stepping effort quickly from the keyboard while writing.

## How it works today

- **Entry points:** the traits/effort control in the composer footer; `composer.effort` (`mod+shift+e`) opens it; `composer.cycleEffort` (`mod+/`) steps effort; the Effort row in the model picker; Settings → Appearance → Effort display (name such as "High" or bars).
- **Behaviour to preserve:**
  - Menu content is generated from the model's option descriptors: radio groups per descriptor, boolean toggles, segmented effort (`EffortSegmentedControl`, `EffortGlyph`, effort segments from `@e6tools/client-runtime/effortSegments`).
  - Options are normalised when the model changes; values the new model lacks fall back to the provider default; an unset value means the provider's own config decides.
  - Claude "Ultrathink" is sent as a prompt prefix, not an API option (`applyClaudePromptEffortPrefix`).
  - Effort display setting switches between word and bars.
  - Compact layouts move the control into the overflow menu (`CompactComposerControlsMenu`).
  - Selections persist with the draft per provider instance (E14-T06) and carry to new threads.
- **Surfaces:** web and desktop. Mobile: model/effort pill in the composer toolbar and thread settings sheet (E32-T03, E32-T07). Server: option descriptors in the provider snapshot.
- **Where the code lives:** `apps/web/src/components/chat/TraitsPicker.tsx` (921), `EffortSegmentedControl.tsx`, `EffortGlyph.tsx`, `composerProviderState.tsx`, `CompactComposerControlsMenu.tsx`, `packages/client-runtime/src/effortSegments.ts`.

## Problems today

- `TraitsPicker.tsx` is 921 lines and also hosts Mode and Permissions sections, so three concerns share one menu.
- Option rendering is generic, so labels vary per provider without a shared vocabulary.

## Remodel goals

- **Experience:** effort reads the same across providers (a shared scale with provider-specific names in the tooltip); the chip shows "Model · effort" as one control.
- **Motion:** effort changes from the keyboard update the label with `numberChange`-style swap; menu uses `pop`.
