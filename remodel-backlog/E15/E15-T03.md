# E15-T03 · Context window meter and compaction

## What it is

Agents can only keep a limited amount of conversation in their **context window**. The context meter in the composer footer shows how full it is (a small ring with a percentage), and its popover gives the percentage, total tokens processed, when automatic compaction happens, and a "Compact context" button. **Compaction** summarises the conversation so far to free space; in E6 Code it is sent to the provider as the `/compact` command and shows in the timeline as a compaction row. For Claude, when a long idle thread is resumed, E6 Code offers to compact first.

## When it is used

- Long sessions where the agent starts forgetting earlier details or slows down.
- Before a big new task in an old thread.
- Coming back to a large Claude thread after more than an hour.

## How it works today

- **Entry points:** hover or focus the meter, then "Compact context"; type `/compact` (E14-T02); Settings → Providers → Claude → "Auto-compact after" (integer 100,000 to 1,000,000; empty uses the default); the resume-after-compaction banner (Claude).
- **Behaviour to preserve:**
  - The meter appears only for providers whose snapshot sets `reportsContextWindow` (today Codex and Claude); usage comes from thread activities, so the footer reserves the meter's slot while thread detail loads to keep controls from jumping (`shouldReserveContextWindowMeter`).
  - "Compact context" is offered only when the provider lists a `compact` slash command (`providerSupportsManualCompaction`) and is disabled with a reason while a send is in flight, settings are not hydrated or the thread is busy. Compaction sends `/compact` as a standalone turn; the draft and its attachments stay in the composer.
  - Popover text: auto-compact threshold when known, otherwise "compacts automatically when needed" with the model's name.
  - Timeline shows a `context-compaction` row (E13-T09); a "compacting" label appears while it runs.
  - Claude resume offer: when a Claude thread has used at least 100,000 tokens and was last updated 70 or more minutes ago, a banner offers to compact before continuing; answering "Don't ask again" suppresses it for that thread.
  - **Per provider (E37-T11):** Codex native `thread/compact`; Claude `/compact` plus the Auto-compact setting; Cursor `/compress`; Grok `/compact`; OpenCode native; Antigravity `/compact`. Claude cannot revert across a compaction boundary (E16-T05).
- **Surfaces:** web and desktop. Mobile shows a "compacting" state in the thread (E32-T01); a mobile meter is not verified. Run details shows context fullness too (E17-T04).
- **Where the code lives:** `apps/web/src/components/chat/ContextWindowMeter.tsx` (171), `ContextWindowMeter.logic.ts`, `ChatView.tsx:7618` (`onCompactContext`), `MessagesTimeline.tsx:2115` (compaction row), `packages/shared/src/claudeCompaction.ts`.

## Problems today

- The meter is invisible for four of six providers with no explanation.
- Cursor's compaction command is `/compress`, but the manual-compaction check looks for a command named `compact`, so Cursor may never get the button (not verified end to end).
- The Claude resume offer is driven by a hard-coded driver check (`provider !== "claudeAgent"`).

## Remodel goals

- **Experience:** the meter is a compact mark (design direction §8) with a word-plus-number tooltip; near full it uses the warning role with a word ("Context nearly full"), never colour alone. Compaction offers what each provider actually supports.
- **Motion:** the percentage changes with `numberChange` only when it moves; the ring never animates continuously.
- **Performance:** meter subscribes to the latest usage value only, not the activity list.
