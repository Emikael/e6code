# E15-T08 · Permission mode and plan mode

## What it is

Two per-thread switches that decide how much the agent may do on its own. **Permission mode** (called runtime mode in code) has four levels: Supervised (ask before commands and file changes), Auto-accept edits (approve edits, ask for other actions), Auto (supported providers approve routine actions themselves; others still ask) and Full access (no prompts). **Plan mode** (interaction mode `plan` versus `default`) asks the agent to produce a plan instead of making changes; the plan then comes back as a card the user can implement (E16-T04).

## When it is used

- Starting risky work in Supervised; letting a trusted refactor run in Full access.
- Asking for a plan first on a large change, then implementing it.
- Setting a team-wide or project-wide default for new threads.

## How it works today

- **Entry points:** Permissions: the chip or menu section in the composer (`ComposerPermissionsMenuSection`), `composer.mode` (`mod+shift+a`), Settings → General → New threads → Permissions (initial default Full access) with a project override. Plan mode: the plan toggle chip in the composer footer, Shift+Tab in the composer, `/plan` and `/default` commands, Mode section of the traits menu.
- **Behaviour to preserve:**
  - Both modes are per thread, stored with the draft (E14-T06) and sent with each turn (E14-T05); new threads take the settings default unless the project overrides it.
  - Permissions has exactly one visible home (`resolveRuntimeModeDisplay`): a labelled chip when the thread's mode differs from the default, otherwise inside the effort menu when the model has one, otherwise an icon-only chip.
  - Plan mode is offered only when the client setting `planModeEnabled` is on (default true) and the provider's snapshot sets `showInteractionModeToggle`; `/plan` and `/default` appear in the `/` menu under the same condition.
  - **Per provider (E37-T11):** Auto uses the provider's own review on Codex, Claude and Cursor; Grok passes `--permission-mode auto` (user docs omit Grok); OpenCode treats Auto as Supervised and offers "Allow once" / "Allow for workspace"; Antigravity falls back to asking and can ask even in Full access. Cursor and Grok set the permission mode as a spawn argument; whether a mid-thread change restarts their session is not verified. Plan toggle: shown for Codex, Claude (SDK `plan` permission mode) and Cursor (ACP `plan`/`architect`); hidden for Grok and OpenCode although their adapters handle plan; unavailable on Antigravity, which has its own native `/plan` command.
- **Surfaces:** web and desktop. Mobile: runtime mode and a Plan/Build toggle in the composer toolbar (legacy plan mode setting) and thread settings (E32-T03, E32-T07). Server: settings defaults and project overrides (E25-T05, E25-T07); adapters map modes.
- **Where the code lives:** `apps/web/src/components/chat/runtimeModeConfig.ts`, `ComposerPermissionsMenuSection.tsx`, `ChatView.tsx:4728-4770` (mode handlers, `toggleInteractionMode`), `ChatView.logic.ts:614`, `ChatComposer.tsx` (Shift+Tab, plan chip), `docs/user/permission-modes.md`.

## Problems today

- Three display modes for one setting make Permissions hard to find.
- The per-provider meaning of "Auto" is only in user docs; the UI says "Supported providers approve routine actions; others still ask" without saying which.
- Plan mode availability is inconsistent with adapter support (Grok, OpenCode).

## Remodel goals

- **Experience:** permissions become a compact mark in the composer footer with a word and icon when not default; the menu states what the current provider does in Auto ("Codex reviews routine actions itself" versus "OpenCode will still ask"). Plan mode is a clear toggle with the composer visibly in "plan" state (placeholder and send label change).
- **Motion:** mode swaps use `iconSwap`; no other animation.
