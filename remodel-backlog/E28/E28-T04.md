# E28-T04 · Usage limit sources and hubs

## What it is

**Usage limit sources** are places outside the providers E6 Code runs that can report subscription quota. Today the only kind is a **CLIProxyAPI hub**: a proxy that pools several subscription accounts; E6 Code reads its management API to show those accounts' windows on the Limits tab. A hub is added to one environment with its URL and a management key that stays on that server. This task also records, per provider, where limits come from.

## When it is used

- A user who routes agents through a CLIProxyAPI hub wants to see the pooled accounts' remaining quota.
- Removing a hub, or diagnosing one that cannot be read.

## How it works today

- **Entry points:** Settings → Providers → Usage providers → Add hub; remove from the same list (with confirmation); the hub's accounts appear on Usage → Limits.
- **Behaviour to preserve:**
  - Dialog: Hub URL (placeholder `https://hub.example.ts.net:8318`), Management key (write-only; "The key stays on that server"), Label (optional, defaults to the hub's host name); the dialog names the environment it is added to. Empty list: "No usage providers configured."
  - Server (`UsageLimitSources.ts`): each `settings.usageLimitSources` entry is polled on the provider health-check interval (from background activity, E25-T12) and on every settings change, and published as one snapshot per source on `subscribeServerConfig`; a failing source keeps its row with `error` so it is visibly configured but unreachable; nothing is persisted. The key lives in the secret store and is redacted in `settings.json`. Hubs can also redeem reset credits (`UsageLimitSourceConsumeResetCreditInput`).
  - Per-provider limit sources (user docs): OpenCode Go local only; Cursor via file CLI login or `CURSOR_AUTH_TOKEN` (`AGENT_CLI_CREDENTIAL_STORE=file` on macOS); Grok via `grok login`; API-key accounts do not report; Codex and Claude native (E28-T02).
- **Surfaces:** web and desktop settings; server polling; limits visible on mobile too.
- **Where the code lives:** `apps/web/src/components/settings/UsageProviderSettings.tsx`, `AddUsageLimitSourceDialog.tsx`; server `apps/server/src/usage/UsageLimitSources.ts`, `cliproxyApi.ts`; contracts `providerUsageLimits.ts`, `usageLimitSourceId.ts`, `settings.ts` (`usageLimitSources`).

## Problems today

- Hubs are configured inside the Providers page but consumed on Usage; neither page links to the other.
- The status of a configured hub (last read, error) is only visible indirectly as a warning on Limits.

## Remodel goals

- **Experience:** each hub row shows its last successful read and its error in words, with a "Test" action; the Limits tab links to where hubs are managed.

## Done when

- [ ] Add, label, remove, write-only key, per-environment placement, polling cadence, error-keeping rows and reset-credit support preserved.
- [ ] Hub status visible on the hub row; Limits links to it.
- [ ] Keys never leave the server (test); dark and light; keyboard reachable.
