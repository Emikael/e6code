# E28-T02 · Limits and pooled subscriptions

## What it is

The **Limits** tab of the Usage page and the per-provider limit views: how much of each subscription's rate-limit windows (for example a 5-hour session window or a weekly window) is left, for every signed-in account, pooled by provider. It answers "can I keep working on this account, and when does it reset?". Codex accounts can also redeem reset credits. The same data powers the `/usage-limits` composer command and the plan-limit card in the thread overview.

## When it is used

- Before a long agent run, to choose an account with room left.
- When an agent hits a limit and the user wants to know when it resets or which other account to switch to.
- Deciding whether to use a Codex reset credit.

## How it works today

- **Entry points:** Usage → Limits tab; Usage refresh button (on Limits it rechecks all providers and hubs); composer `/usage-limits` (shows the current model's limits above the composer, only for clients that declare `usageLimitsCommand`); thread overview plan-limit card; provider settings (per-provider `UsageLimitsSection`); mobile Settings → Usage → Limits and the per-account screen; iOS and Android subscription widgets.
- **Behaviour to preserve:**
  - Pooled view (`UsageLimitsPooled`): one pool per provider; window cards (5 h, weekly, …) with a segmented bar, one segment per account (avatar initials) and a hover popover (plan, % left, resets at, restores); legend rows; pace reading with icon and words ("ahead of pace" / "behind pace"); low state with warning icon and words; stale state; warning notices for unreadable sources; redeemable reset credits ("Use reset" → confirm "Use a reset credit?").
  - Refresh: switching to Limits triggers an automatic refresh; automatic checks happen at most every five minutes per environment; manual refresh calls `refreshProviders` on every selected connected environment. A page-level "now" clock drives relative reset times.
  - Empty: no provider reports limits.
  - Sources per provider (docs and the capability matrix): Codex native rate-limit events plus a fetcher and reset credits (redemption serialised per account); Claude native events plus a fetcher, with a "Paused for usage limit" thread state; Cursor via the billing API with a stored token (file CLI login or `CURSOR_AUTH_TOKEN`; `AGENT_CLI_CREDENTIAL_STORE=file` on macOS); Grok via `grok login` credentials; OpenCode Go local only; Antigravity none (quota errors appear as messages); API-key accounts do not report. External hubs: E28-T04.
  - Server: adapters emit `account.rate-limits.updated`; `ProviderUsageLimitsIngestion` merges into the instance snapshot delivered with provider status; per-provider fetchers read local credentials.
- **Surfaces:** web, desktop, mobile (pooled view, account screen, widgets), server. Hitting a limit in a thread and continuing in a new thread is E15-T04.
- **Where the code lives:** `apps/web/src/components/usage/UsageLimitsPooled.tsx` (577), `UsageLimits.tsx` (456), `components/chat/ComposerUsageLimits.tsx`, `InspectorOverview.tsx`; `packages/shared` limits helpers; `packages/client-runtime/src/state/usage.ts`; server `provider/providerUsageLimits.ts`, `Layers/ProviderUsageLimitsIngestion.ts`, `Layers/*UsageLimits.ts`, `codexResetCredit.ts`, `packages/contracts/src/providerUsageLimits.ts`.

## Problems today

- Refresh fans out `refreshProviders` (a full provider status refresh) to every environment just to update limits.
- A page-level timer re-renders the page for relative times.
- Account details live in hover popovers, which are unreachable on touch and hard to reach by keyboard.

## Remodel goals

- **Experience:** per provider, the account with the most room is obvious; reset times are absolute plus relative; low and exhausted states use icon plus word; account details are reachable without hover.
- **Motion:** bars fill without animation loops; a refresh updates values with `numberChange` once.
- **Performance:** a limits-only refresh RPC rather than full provider refresh, if the server supports it; relative-time ticks only re-render the labels.

## Done when

- [ ] Pools, windows, per-account segments, pace, low, stale, empty, source-warning and reset-credit flows preserved, with the five-minute automatic refresh limit.
- [ ] `/usage-limits`, the thread overview card and provider settings use the same view model (shared with mobile in `client-runtime`).
- [ ] Account details reachable by keyboard and touch; dark and light; status never by colour alone.
- [ ] Per-provider behaviour matches the capability matrix, including "does not report" for API-key accounts.
