# E16-T04 · Plan follow-up and implement in new thread

## What it is

In plan mode (E15-T08) the agent researches and returns a **proposed plan** instead of changing code. The plan appears as a card in the timeline (collapsible Markdown with copy, download and save-to-workspace) and the composer switches to a plan follow-up state: **Implement plan** runs it in the same thread (switching back to default mode), **In new thread** starts a fresh thread titled from the plan, and anything the user types instead is sent as a refinement of the plan.

## When it is used

- Large or risky changes where the user wants to review the approach first.
- Handing a plan to a clean thread (and worktree) to keep the planning conversation separate.
- Iterating on a plan ("drop step 3, add tests first").

## How it works today

- **Entry points:** plan card actions (expand/collapse, copy, download as Markdown, save to workspace dialog); frontier strip buttons (E16-T01); composer plan follow-up banner and Implement split button; typing in the composer and sending (refinement); Antigravity's native `/plan` command.
- **Behaviour to preserve:**
  - The plan card shows a title derived from the plan (`proposedPlanTitle`), collapsed preview with fade and "Expand plan"; copy (with failure toast "Could not copy plan"), download with a generated filename, save to workspace through a dialog.
  - Implement plan (same thread): switches interaction mode to default and sends `PLEASE IMPLEMENT THIS PLAN:\n<plan>` through the send pipeline.
  - In new thread: creates a thread titled from the plan (`buildPlanImplementationThreadTitle`) and sends the implementation prompt there; the original keeps the plan.
  - If the composer has text, sending treats it as a refinement of the plan instead of implementing (`resolvePlanFollowUpSubmission`).
  - Buttons disable while a send is busy; on failure the composer snapshot is restored.
  - Plan-agent selection is healed when the selected agent disappears (`planAgentSelectionHeal.tsx`).
  - **Per provider (E37-T11):** proposed plan cards appear for Codex, Claude, Cursor and Grok; not seen for OpenCode and Antigravity. Plan mode toggle hidden for Grok and OpenCode; Antigravity has no E6 plan mode and uses its own `/plan` command, whose output path is not verified.
- **Surfaces:** web and desktop. Mobile renders plan steps in the feed and has a Plan/Build toggle (E32-T01, E32-T03); a mobile "Implement" action is not verified. Server: `turn.proposed.*` events from adapters.
- **Where the code lives:** `apps/web/src/components/chat/ProposedPlanCard.tsx` (260), `ComposerPlanFollowUpBanner.tsx` (20), `proposedPlan.ts`, `ChatView.tsx:9424-9770` (follow-up and implement handlers), `ChatView.logic.ts:951, 1370`, `planAgentSelectionHeal.tsx`.

## Problems today

- The "plan ready" state shows in three places: the card, the frontier strip and the composer banner.
- The implementation prompt is a hard-coded English prefix visible in the user's message history.
- Per-provider plan support is inconsistent (cards from Grok but no toggle).

## Remodel goals

- **Experience:** the plan card is the turn's result (a raised card like the changed-files card); the decision surface (E16-T01) offers Implement (primary) and "In new thread"; typing shows the send button as "Refine plan" so the user knows what Enter will do.
- **Motion:** "In new thread" is a deeper move: the new thread enters as a forward transition while the plan card's title travels into the new thread's header (match cut) or the switch is a cut. Expanding the plan uses the `layout` preset in the viewport only.

## Done when

- [ ] Implement, In new thread, refinement, copy, download and save-to-workspace behave as above, with composer restore on failure.
- [ ] Plan follow-up shows in one place (decision surface) plus the card.
- [ ] Per-provider plan behaviour recorded (including Antigravity `/plan`, OpenCode, Grok) and read from capabilities.
- [ ] Dark and light reviewed; long plans readable with keyboard expand/collapse.
- [ ] Tests for follow-up resolution and title/filename helpers kept.
