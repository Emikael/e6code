# E16-T03 · Questions from the agent

## What it is

Agents sometimes stop to ask the user something: which environment to target, which image format to use, whether to keep a dependency. E6 Code shows these as a question panel in the composer: one question at a time ("Environments 1/3"), with options to pick (single or multiple choice), a free-text answer in the composer editor, files or images attached to each answer, Previous / Next, and Dismiss. Answers go back to the agent together; answered questions remain visible in the timeline as a short history.

## When it is used

- The agent needs a decision only the user can make before it continues.
- Codex asks questions while it keeps working (asynchronous questions, answered as a new message).
- The user wants to answer with a screenshot or file ("this is what the error looks like").

## How it works today

- **Entry points:** the composer question panel; "Answer below" on the frontier card; number keys 1–9 select options when focus is outside editable fields; the composer editor holds the custom answer; "Attach files" or paste images into a custom answer; Dismiss ("Dismiss question without answering").
- **Behaviour to preserve:**
  - Each request can hold several questions; progress shows "n/N"; Previous and Next move between them; sending from the composer advances the active question.
  - Single-select: picking an option selects it optimistically and auto-advances after 200 ms. Multi-select: options toggle in place. Number keys follow the same rules and are disabled while the panel is collapsed or a response is in flight.
  - Custom answer: typed in the composer editor with a mention-aware cursor; a custom answer overrides selected options; if the user switches question, a displaced custom answer is carried into the prompt rather than lost (`carryDisplacedCustomAnswerIntoPrompt`).
  - The panel can collapse; a question's subagent is named ("<subagent> needs your answer").
  - **Attachments per question:** each question keeps its own attachments, stored as composer drafts under a per-question draft key (`questionAttachmentDraftId(environment, thread, request, question)`) in the persisted draft store; up to 100 files per set of answers with the normal composer size limits; failed uploads can be retried or removed; the draft is preserved when a submit fails. Answers are sent with `attachmentsByQuestionId` on `thread.turn.answer`. Attachments stay in history and are cleaned up on revert and thread delete.
  - Whether selected options and custom text survive a reload is not verified (option selections live in `ChatView` component state; attachments persist).
  - Dismiss closes the question without a reply. Codex asynchronous questions: the answer becomes a new message, dismiss sends nothing, and they need a Codex version that supports them; manually settling a thread dismisses unanswered async questions (E09-T03).
  - Answered questions render as `QuestionAnswerHistory` in the timeline.
  - Pending questions hold the message queue (E15-T05).
  - **Per provider (E37-T11):** all six can ask; Codex both blocking and async (async survives restart); OpenCode as forms; Antigravity requires fixed choices even in Full access.
- **Surfaces:** web and desktop. Mobile: `PendingUserInputCard` with options, free text and `QuestionAttachments` (E32-T06). Server: `user-input.requested` / `user-input.resolved` activities, attachment claim per question (`06:F-11`).
- **Where the code lives:** `apps/web/src/components/chat/ComposerPendingUserInputPanel.tsx` (312), `pendingUserInput.ts`, `questionAttachments.ts`, `ChatView.tsx:9195-9424`, `MessagesTimeline.tsx:5704` (answer history), `@e6tools/client-runtime/work-log/user-input`.

## Problems today

- Answer state is split between ChatView state (selections, custom answers) and the persisted draft store (attachments), so a reload may keep files but lose choices (not verified).
- The panel and the frontier card both announce the same question (E16-T01).

## Remodel goals

- **Experience:** questions use the decision surface (design direction §8): answer options as large selectable rows with number hints, free text below, attachments inline with progress and Retry/Remove; multi-question flows advance with `sideBySide` (direction by Previous/Next). Answered questions collapse into compact log rows.
- **Motion:** option selection applies instantly (≤ 90 ms visual); the 200 ms auto-advance remains a deliberate pause, not an animation wait; reduced motion uses a fade.

## Done when
