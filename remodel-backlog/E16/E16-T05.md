# E16-T05 · Revert and edit from here (checkpoint rewind)

## What it is

"Edit from here" rewinds a thread to just before one of the user's messages: the later conversation is removed, the provider's own conversation is rolled back to match, and the message's text and attachments come back into the composer so the user can change and resend it. In threads that run in their own worktree, the user can also restore the files to how they were at that point. This works because E6 Code saves a **checkpoint** at the end of every turn: a snapshot of the workspace stored as a hidden Git ref that never touches the user's branch. Checkpoints also power the per-turn diffs.

## When it is used

- The agent went down the wrong path after a vague prompt; the user rewrites the prompt and tries again.
- A turn broke the build in a worktree thread and the user wants files and conversation back to before it.

## How it works today

- **Entry points:** the undo icon "Edit from here" on a user message (hover actions, `MessagesTimeline.tsx:2548`); revert from a turn's changed-files section (E13-T10). The `thread.undo` keybinding (`mod+z`) is not this feature: it reverses the latest thread lifecycle action (pin, settle, snooze, archive) and belongs to E09-T03.
- **Behaviour to preserve:**
  - Dialog "Edit from here?": "Rewind chat to before this message. Your prompt and attachments return to the composer." In a shared checkout it adds "Files stay as they are because this thread shares the project directory." and offers only "Revert and keep changes"; in a worktree thread it also offers "Revert files too" (destructive styling).
  - Refused while a turn is running or a send is in flight ("Interrupt the current turn before reverting checkpoints."), while attachments are still preparing ("Wait for attachments to finish preparing before rewinding."), and when restoring the message's attachments would exceed the composer's limits ("Make room for this message's attachments in the composer before rewinding.").
  - The restored prompt is appended to any text already in the composer (blank line between); images and files are re-attached (downloaded back from the server as needed); the cursor lands at the end and the composer is focused. The composer is `inert` while the rewind runs (`rewindingThreadKeys`).
  - The button is hidden or disabled when the provider cannot roll back (`supportsConversationRollback === false`), and for paint-only held timelines.
  - **Server:** at turn start the checkpoint reactor ensures a pre-turn baseline; at turn completion it writes a checkpoint with a temporary `GIT_INDEX_FILE` (`git add -A`, `write-tree`, `commit-tree`) and `update-ref refs/e6/checkpoints/<base64url(threadId)>/turn/<n>`, then emits `thread.turn.diff.complete` with file counts. Revert (`thread.checkpoint.revert`, `thread.conversation.revert`) verifies isolation, restores the workspace from the ref when files are included, rolls back the provider conversation (rejecting first if the provider cannot), deletes later refs, emits `thread.revert.complete`, and the projector prunes later messages, activities and attachments. Non-Git workspaces skip checkpoints. Turn duration ends when the session settles; late checkpoints do not extend it.
  - **Per provider (E37-T11):** conversation rollback on Codex and Claude (Claude not across a compaction boundary, so support depends on thread state), OpenCode (adapter implements it; not verified end to end); not on Cursor, Grok or Antigravity (Antigravity docs: revert and edit-and-resubmit unavailable).
- **Surfaces:** web and desktop. Mobile: not verified whether mobile offers edit-from-here. Server: `CheckpointReactor`, `CheckpointStore`, `CheckpointDiffQuery`.
- **Where the code lives:** `apps/web/src/components/ChatView.tsx:7487-7620` (`onRevertToTurnCount`), `:11200-11245` (dialog), `MessagesTimeline.tsx:2548`, `lib/chatThreadActions.ts`; server `apps/server/src/orchestration/Layers/CheckpointReactor.ts` (1,109), `checkpointing/CheckpointStore.ts`, `CheckpointDiffQuery.ts` (292), `Diffs.ts`.

## Problems today

- The revert affordance is hidden at narrower widths (screenshot 08), so the feature is easy to miss.
- No way back after a revert (no undo); later turns and their checkpoint refs are deleted.
- The per-provider unavailability is a hidden button, not an explanation.
- Table `checkpoint_diff_blobs` (migration 003) is no longer referenced by code.

## Remodel goals

- **Experience:** "Edit from here" is always reachable from a user message (hover, context menu, keyboard focus) and, where the provider cannot rewind, shows the reason in words. The dialog says exactly what will be lost (N later turns) and what happens to files.
- **Motion:** the rewind is a user-caused move: the message's text travels back into the composer (`matchCut`, reverse of set-piece 3.2), and the removed turns cut away (no slow fade of many rows).
- **Performance:** pruning a long thread must not stall the timeline; the client applies the revert from the `thread.revert.complete` receipt, never from timers.
