# E34-T07 · Mobile usage pages

## What it is

The Usage pages show what agent work has cost and how much of each subscription is left. **Usage** has two tabs. The **Usage** tab totals spend or tokens over a period across the user's environments, with a daily chart, totals, per-provider and per-model breakdowns and Jev routing savings. The **Limits** tab shows pooled subscription limit windows (for example the 5-hour session window and the weekly window) for each provider, with one segment per signed-in account. Tapping an account opens the **Usage limit account** page with that account's windows and reset credits.

## When it is used

- Checking how much a week of agent work cost, or which model consumed the most tokens.
- Before starting a big task, checking whether Claude or Codex has enough session or weekly quota left, and when it resets.
- Redeeming a reset credit for a provider account when a window is exhausted.

## How it works today

- **Entry points:** Settings > App > Usage; deep link `settings/usage` (and `?tab=limits`); the account page from the Limits tab only. The composer's `/usage-limits` report and the in-thread plan-limit card are separate (E32-T09); the home-screen widgets show the same quota data (E35-T02).
- **Behaviour to preserve:**
  - Usage summaries are requested from each selected, connected environment and combined; an environment that cannot report shows its saved totals with a status word rather than dropping out (`usageEnvironmentSelection.ts`).
  - Period and metric choices; daily series built by `usageChartData.ts`; provider order and labels from `usageProviders.ts`.
  - Unpriced models are flagged rather than counted as zero cost.
  - Limits are pooled across accounts and environments (shared `client-runtime` usage state), with pace and reset times; account emails are masked until revealed.
  - Reset credits: redeem with explicit result messages; no credits shows a clear empty state.
  - Loading and partial states per environment.
- **Surfaces:** web and desktop have the Usage page (E28-T01) with period-over-period change, chart/table toggle, provider share, "Where the cost went", custom model prices (E28-T03), and the Limits tab (E28-T02) with the same pooled model and hover popovers; usage limit sources and hubs (E28-T04) are configured on web only. Server: usage tracking and limit sources (`07:F-48`).
- **Platform differences:** iOS draws the daily chart with a native SwiftUI chart (`UsageDailyChart.ios.tsx` through `@expo/ui`); Android uses the shared React Native chart (`UsageDailyChart.tsx`). Headers and the environment filter follow each platform's Settings chrome; segmented controls are native on iOS and Material on Android.
- **Where the code lives:** `apps/mobile/src/features/usage/UsageRouteScreen.tsx` (617), `UsageLimitsSection.tsx` (360), `UsageLimitsPooled.tsx` (385; `UsageLimitAccountScreen` near line 282), `UsageDailyChart{,.ios}.tsx`, `usageChartData.ts`, `usageEnvironmentSelection.ts`, `usageProviders.ts`, `src/state/usage.ts`, `@e6tools/client-runtime/state/usage`.

## Problems today

- Two chart implementations (SwiftUI and React Native) must agree on data, colours and accessibility.
- The account page has no deep link, so it cannot be reached from a widget or notification.
- Feature differences with web (custom prices, comparison with the previous period, table view) are undocumented.

## Remodel goals

- **Experience:** answer two questions at a glance: "what did this cost" and "how much is left". Totals roll once with a number change, charts follow the data-visualisation rules (one hue family per series role, values readable without touch-and-hold), and pace is words plus an icon.
- **Motion:** totals animate once on first load or period change; nothing loops; switching tabs is a cut.
- **Performance:** cached summaries show instantly on open; refreshing several environments never blocks scrolling.
