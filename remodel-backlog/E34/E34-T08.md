# E34-T08 · Mobile about, storage, diagnostics, licenses, legal

## What it is

The "About E6 Code" group in mobile Settings: the **About** page (app version, build variant, a hidden over-the-air update check), **Client Storage** (sizes of the phone's per-environment caches, with Clear actions), **Diagnostics** (a list of startup crashes from the last 7 days, copyable as a report), **Open source licenses** (list and detail of third-party notices), and **Legal** (privacy policy, security policy, terms and legal notices shown in an in-app full-screen document view).

## When it is used

- Checking which version is installed before reporting a bug, or forcing an update check after a fix was published.
- Freeing space or fixing stale data by clearing an environment's cache.
- After the app crashed on launch: copying the crash report to send to the maintainer (TestFlight and the stores strip these crashes from their reports).
- Reading licences or the privacy policy, often required by app-store review.

Layout in words:

- **About** (`settings/about`): titled "About E6 Code". A "Version" row showing the version and, for non-production builds, the variant ("1.2.1 · Preview"), with a small status line under it during an update check (checking, downloading, restarting, up to date). Tapping the version five times starts an update check (a hidden gesture). Section "App" with rows: Client Storage, Diagnostics, Open source licenses, Legal (Legal opens full screen).
- **Client Storage** (`settings/client-storage`): titled "Client Storage". Section "Environment caches": one row per environment with its cached size (shell, threads, server config, VCS refs, favicons) and a "Clear N MB" button (confirm). Section "Actions": "Clear N MB" / "Clear caches" for everything, with the note that clearing caches never removes environment connections, credentials or account data.
- **Diagnostics** (`settings/diagnostics`): titled "Diagnostics". Section "Startup crashes" listing each crash (time, description, top frames) or "No startup crashes" / "Crash log unavailable" / a loading state. Section "Actions" with "Copy crash report" (becomes "Copied").
- **Open source licenses** (`settings/open-source-licenses` and `settings/open-source-licenses/:entryKey`): a searchable list of packages with their licence; a "License notice" detail page with the full text.
- **Legal** (`settings/legal`, root full-screen modal): a WebView of the requested document from the marketing site, a close button ("Close legal document") and an open-externally button. Links leaving the allowed set open in the system browser.

## How it works today

- **Entry points:** Settings > App > About E6 Code; deep links `settings/about`, `settings/client-storage`, `settings/diagnostics`, `settings/open-source-licenses[/:entryKey]`, `settings/legal`.
- **Behaviour to preserve:**
  - Version label hides the variant for production and never mislabels a production build as development when the variant is missing.
  - Hidden update tap: 5 taps trigger an `expo-updates` check through `app-updates.ts` (download, defer install, restart); unavailable in builds without updates (E31-T10 owns OTA behaviour).
  - Cache summary per environment from the mobile SQLite database (`persistence/mobile-database.ts`, `state/client-cache-state.ts`); per-environment and global clear with confirmation; clearing never touches connections, secure-store secrets or account data.
  - Crash list comes from the `expo-updates` log (`Updates.readLogEntriesAsync`) filtered to fatal JS exceptions written by ErrorRecovery during startup, over a 7-day window (`crash-log-model.ts`); the copied report includes app identity (version, variant, update id).
  - Licence data generated at build time (`mobileThirdPartyLicenses.ts`, typed in `src/types/mobile-third-party-licenses.d.ts`) with search and detail.
  - Legal URLs derive from `EXPO_PUBLIC_MARKETING_SITE_URL` (default `https://e6code.com`): `privacy-policy`, `security-policy`, `terms-of-service`, `legal`; only allow-listed document URLs load in the WebView.
- **Surfaces:** web and desktop have About in Settings > General (version, desktop update checks and update track, E12-T05, E30-T05), Diagnostics with live server processes, resource history and trace diagnostics (E25-T14, a different thing: server health, not app crashes), and Open source licenses (E25-T15). Legal pages live on the marketing site (E40-T02). Client storage has no web equivalent; web has server Storage cleanup (E25-T11).
- **Platform differences:** iOS shows these as pages in the Settings form-sheet stack with native grouped lists; Android uses `SettingsScreen` with `AndroidScreenHeader`. The Legal modal is a `fullScreenModal` on both. The crash source is the same `expo-updates` log on both platforms.
- **Where the code lives:** `apps/mobile/src/features/settings/SettingsAboutRouteScreen.tsx` (149), `SettingsClientStorageRouteScreen.tsx` (206), `features/diagnostics/SettingsDiagnosticsRouteScreen.tsx` (167), `crash-log-model.ts`, `SettingsOpenSourceLicensesRouteScreen.tsx` (258), `mobileThirdPartyLicenses.ts`, `SettingsLegalRouteScreen.tsx`, `components/SettingsLegalDocumentRouteScreen.tsx` (182), `lib/legal-document-url.ts`, `features/updates/app-updates.ts` (622), `persistence/mobile-database.ts`, `state/client-cache-state.ts`.

## Problems today

- The update check is hidden behind five taps; users cannot discover it, and the user docs only describe background updates.
- "Diagnostics" means app startup crashes on mobile but server health on web; the shared name hides the difference.
- Only startup crashes are captured; crashes after startup or native crashes are not listed (see E35-T04).

## Remodel goals

- **Experience:** a plain, trustworthy page: version and update status visible with a real "Check for updates" action (or a recorded decision to keep it hidden), storage sizes that explain what clearing does, and a crash report flow that is one tap to copy or share.
- **Motion:** none beyond native pushes; copy confirms with an icon swap and a light haptic.
- **Performance:** cache size computation must not block opening the page; show sizes as they arrive.

- [ ] Crash parsing and legal URL tests kept (`crash-log-model.test.ts`, `legal-document-url.test.ts`).
