# E25-T05 · General settings

## What it is

The General settings page (`/settings/general`): the behaviour defaults for new threads, the sidebar, notifications, diffs, the composer, background work, confirmation dialogs, generated text, and the About block with the app and server version and updates. It is the densest page in the app (about 35 rows in one 1,200-line component) and mixes rows saved on this device with rows saved on the selected environments.

## When it is used

- First setup: choosing a default model, permission mode and whether new threads start in a worktree.
- Tuning daily feel: send shortcut, queue vs steer, notifications, diff defaults, time format.
- Turning on automation: auto-settle of merged or idle threads, continue threads after restarts, Jev routing.
- Checking the version, installing an app update, or switching the update track.
- Getting to Diagnostics or Open source licenses.

## How it works today

- **Entry points:** settings nav "General"; `/settings` redirects here; palette "Check for updates" lands on `#about-version`; settings search for each row; Composer and keybinding docs point here for Send shortcut and Follow-up behavior.
- **Behaviour to preserve — every control on the page.** "Client" is saved on this device; "server" is saved in `settings.json` on each environment in scope; "project-scopable" can also be overridden per project or checkout (E25-T02).

## Problems today

- One component renders every row and re-renders all of them on any settings change (no row-level memoisation).
- Device rows and server rows are interleaved under the same headings ("Behavior" holds diff layout next to response streaming and Jev routing), distinguishable only by a small marker.
- Response streaming, Jev routing and Background activity are agent or server policy, not "behavior" of this client, yet sit in the same list.
- "Restore device defaults" in the header also resets server rows (see E25-T03).

## Remodel goals

- **Experience:** regroup by what the user is deciding (new threads, the sidebar and notifications, the composer and diffs on this device, automation on the environment, updates), and make the device/environment split visible at section level. Keep every row; any retirement (for example the Legacy section after E09-T10 retires the legacy sidebar) is an explicit decision.
- **Motion:** none beyond the standard control states; switching toggles applies instantly (design direction 3.10); the Token streaming warning uses the dialog moment.
- **Performance:** a change to one row re-renders that row only; the page renders under the settings route budget.
