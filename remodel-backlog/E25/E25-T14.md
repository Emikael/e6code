# E25-T14 · Diagnostics and resource telemetry

## What it is

The Diagnostics page (`/settings/diagnostics`, a detail page under General): a view into one environment's health for debugging. It shows live resource use of the E6 system (server, providers, terminals, desktop processes and the monitor itself), resource history, the live process tree with the ability to signal a stuck process, and an analysis of the server's trace log (recent failures, the most common failures, slowest spans, span logs). The data comes from a native resource monitor (a Rust helper) and the server's trace file.

## When it is used

- E6 Code or an agent is slow, hot or using a lot of memory, and the user wants to know which process.
- A provider process is stuck and needs SIGINT or SIGKILL.
- Reporting a bug: copying trace ids, opening the logs folder, finding the failing span.

## How it works today

- **Entry points:** General → Diagnostics → "View diagnostics"; deep link `/settings/diagnostics`. Not in settings search. Each section has its own refresh.
- **Behaviour to preserve:**
  - **Resource monitor** (`ResourceTelemetryDiagnostics.tsx`): status chip (for example "Native unavailable"), "Updated …" with refresh; E6 system footprint tiles (current CPU, resident memory, process count with starts/exits, read and write throughput, CPU speed limit/thermal state) and per-group breakdown (Backend + agents, Desktop, Monitor overhead); "Sampling every 5 seconds". **Host & collection**: host state (power, idle, lock, thermal from the desktop host, or "Desktop host signals not connected"), collection health (native process monitor available or "Resource monitor binary was not found for <platform>"), "Retry monitor". **Resource timeline**, **Live process tree**, **Instrumented application I/O**.
  - **Live Processes** (`DiagnosticsSettings.tsx`): tree of the server's child processes labelled Agent, Subprocess or Process with CPU and RSS, totals (Child Processes, Memory, Server PID) with tooltips explaining what is counted; per-process "Send SIGINT" and "Send SIGKILL" with confirmation, refusing processes that are not children of the server ("Process already exited").
  - **Resource History**: process history period select, bucket sparklines with accessible labels.
  - **Trace Diagnostics**: span count, failures, slow spans, parse errors, "Open logs folder" through the preferred editor (error when no editor is available); Latest Failures, Most Common Failures, Slowest Spans, Span Logs, Top Span Names; copy trace id.
  - **Environment:** shows the scope's representative environment (with "All environments" selected it shows the primary connected environment, without saying which).
  - Server: monitor protocol v3 (configure, external processes, sample interval, streaming on/off, sample now, process table, read history, shutdown), bounded history (1 h, 3,600 snapshots, 20k entries, 64 MiB), streaming only while diagnostics have subscribers; desktop telemetry merged through a private pipe; process identity includes start time to survive PID reuse; Windows packages ship only the Windows binary, so WSL backends lack native telemetry.
- **Surfaces:** web and desktop UI; server and desktop collect. Mobile "Diagnostics" is different: a 7-day startup crash log with "Copy crash report" (E34-T08).
- **Where the code lives:** `apps/web/src/components/settings/DiagnosticsSettings.tsx` (1,319), `ResourceTelemetryDiagnostics.tsx` (1,281), `ProcessSignalActions.tsx`; server `apps/server/src/resourceTelemetry/*` (`NativeTelemetryClient.ts` 1,118, `DesktopTelemetryReceiver.ts` 719, `Model.ts` 608), `diagnostics/TraceDiagnostics.ts` (493), `ProcessDiagnostics.ts`, `ProcessResourceMonitor.ts`, `native/resource-monitor/src/main.rs` (1,334); `docs/internals/resource-telemetry.md`.

## Problems today

- Two 1.3k-line components; many labelled bucket elements re-rendered by polling driven by a relative-time tick.
- The page does not say which environment it describes, and offers no environment picker of its own.
- Section titles mix sentence case and title case; tiles use all-caps mono labels against the type rules in the design direction.

## Remodel goals

- **Experience:** an explicit environment selector and header ("Diagnostics for <machine>"); sections ordered by the question a user asks (what is slow now, what failed, what to send in a bug report).
- **Motion:** numbers that change while watching use tabular figures and `numberChange` at most once per sample; charts follow the data rules (no animated loops, values readable without hover).
- **Performance:** history rendered on a single canvas or SVG path rather than one element per bucket; streaming subscription only while the page is visible, so the monitor stops streaming when it is closed (it already stops with no subscribers).

## Done when

- [ ] Every section, tile, signal action with confirmation, copy, open-logs and refresh above exists on the v2 page.
- [ ] Unavailable-monitor, desktop-signals-missing and WSL states are explained in words.
- [ ] The described environment is named and selectable.
- [ ] Idle CPU of the page measured with streaming on; no frames rendered without new samples.
- [ ] Dark and light; keyboard reachable; status chips pair colour with words.
