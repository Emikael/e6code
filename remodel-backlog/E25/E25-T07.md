# E25-T07 · Project settings and defaults

## What it is

The Project page (`/settings/projects`) and the "project defaults" rows that let one project behave differently from its environment. A **project** is an environment-local workspace record rooted at a directory; the same repository on two machines is two **checkouts** that the sidebar can group into one logical project. The Project page manages one project's identity (name, icon), its checkouts, its actions (project scripts from `e6.json`) and its removal. Project defaults are the same server rows that appear on General, Integrations and Source Control, but written as overrides for the selected project or checkout, with inheritance and "Reset to inherit".

## When it is used

- Renaming a project or giving it a recognisable icon or favicon.
- Seeing which machines have a checkout of the project, and removing a stale one.
- Editing the project's actions (run buttons, setup scripts) and noticing when `e6.json` is invalid or differs between machines.
- Making one repository use a different default model, permission mode, worktree mode, auto-pull, merge method, writer model, browser access or cleanup rule than the rest.
- Removing a project from one machine or everywhere.

## How it works today

- **Entry points:** pick a project in the scope breadcrumb (the "Project" nav item only appears in a project or checkout scope); deep link `/settings/projects?project=…[&checkout=…]`; mobile Settings → Projects & threads → Overview. Project defaults rows on General ("New threads"), Integrations ("Browser": Agent browser access) and Source Control ("Repositories": Automatically pull, Default merge method).
- **Behaviour to preserve:**
  - **Project section:** Name (rename), Project icon (icon set picker, emoji, monogram with colour, image from a repository file via the favicon/file picker, or Automatic; the icon picker is lazy-loaded).
  - **Checkouts:** one row per environment checkout with its path and a Remove action.
  - **Actions:** list of project scripts per checkout (run buttons, setup scripts; each bindable as `script.<id>.run`), an action editor dialog, import from `e6.json`, notices "Different actions across environments" and "e6.json is invalid".
  - **Danger:** Remove checkout, Remove project everywhere, or Remove all entries (confirmations).
  - States: no project chosen (notice), project missing, single vs multiple checkouts, invalid `e6.json`.
  - **Project defaults** (`ProjectDefaultsSettings`): the 17 project-scopable keys (list in E25-T02) are edited with the same rows as the environment defaults; at project scope a row shows its inheritance chain and "Reset to inherit", and a page-level "Reset all"; at environment scope a row can list projects that override it and clear those overrides. The workspace row honours a checkout's `e6.json` `defaultThreadEnvMode` when no override exists. The default model is refused when unavailable on any target ("Select that environment to choose its model separately"). Model and permission rows reuse the composer pickers (`ProviderModelPicker`, `TraitsPicker`, `runtimeModeConfig`).
- **Surfaces:** web and desktop. Mobile: Settings → Project overview (rename, checkouts and worktrees, per-project overrides; `SettingsProjectOverviewRouteScreen.tsx`, `SettingsProjectOverridesSection.tsx`; E34-T05/T06). Server stores overrides in `settings.json` (`ProjectSettingsOverrides`) and project scripts (`defaultProjectScripts`); `e6.json` is read from the checkout.
- **Where the code lives:** `apps/web/src/components/settings/ProjectsSettings.tsx`, `ProjectSettingsPanel.tsx` (sections at 386–545), `ProjectActionsSettings.tsx`, `ProjectActionsList.tsx`, `useProjectScriptSettings.ts`, `ProjectIconPickerDialog.tsx` (254, lazy), `ProjectFaviconPickerDialog.tsx`, `ProjectDefaultsSettings.tsx` (459), `SettingInheritance.tsx`, `packages/shared/src/projectSettings.ts`.

## Problems today

- A project's overrides are spread across four pages (General, Integrations, Source Control, Storage); the Project page itself does not show which settings are overridden for it.
- The Project nav item appears and disappears with the scope, which makes the page hard to find.
- The capture could not open the editor for an existing action by clicking its row (gaps.md); whether that is a capture limit or a bug was not verified.

## Remodel goals

- **Experience:** the Project page becomes the home of everything about one project, including a summary of its overrides with links to each row and one "Reset all overrides". Removing a checkout or project states exactly what is deleted (records vs files).
- **Motion:** dialogs use the standard dialog moment; icon changes in the sidebar update instantly.

## Done when

- [ ] Name, icon (all icon kinds, including persisted Lucide-name icons mapped through the icon layer), checkouts, actions with drift and invalid-file notices, and all three removal actions work as today.
- [ ] Every project-scopable key can be overridden, inherited, reset and listed from the Project page, with the e6.json workspace layer.
- [ ] The page is reachable without first changing the scope (for example a project list or palette command "Project settings…").
- [ ] Dark and light; keyboard reachable; confirmation dialogs name what is removed.
- [ ] Existing `projectSettings` and project-defaults tests pass against the v2 code.
