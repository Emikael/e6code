# E25-T10 · SnapShot settings and setup

## What it is

The SnapShots page (`/settings/snap-shot`, desktop only) and its setup dialog. A **SnapShot** captures another application's window into the current draft with a global shortcut (default: both Shift keys on macOS and Windows), adding the app name, window title, icon and, optionally, the app's accessibility text. Setup walks through operating-system permission and the shortcut, with very different steps per platform and Linux desktop.

## When it is used

- Turning SnapShots on for the first time (two-step setup).
- Changing the capture shortcut or fixing one that stopped registering.
- Choosing whether to include app text (and so whether Accessibility permission is needed on macOS), and turning off the sound, flash or animation.

## How it works today

- **Entry points:** settings nav "SnapShots" (device-only page, scope breadcrumb hidden); settings search ("snap-shot-enabled", "snap-shot-accessibility", "snap-shot-shortcut" and others); the capture shortcut itself.
- **Behaviour to preserve:**
  - Rows: Enable switch with status text; Include app text (attach accessibility data or screenshot only; turning it off drops the Accessibility permission need on macOS); Capture shortcut (record control: modifier pairs or chords, collisions refused; per-Linux-backend states pending/verified/registered); Capture sound (Whoosh or Click, with preview); Flash captured window; Animate snapshots (OS reduced motion disables the animation).
  - Setup dialog: two steps, access then shortcut, per backend: macOS permissions (Screen Recording, Accessibility, with the permission checklist), Linux GNOME "E6 Code SnapShots" extension, KDE Plasma 6 capture helper, Hyprland/Omarchy helper (with Review changes and backup), Niri binding via gdbus, other Wayland desktops via the screenshot portal or a manual window picker ("picker-only" mode). "Finish later" turns capture off but keeps installs.
  - States: unavailable platform (web), setup needed per backend, shortcut pending/verified/registered, picker-only mode.
  - Pending captures are kept on disk until attached and survive a restart; an attachment shows whether accessibility data was included (E22-T04).
- **Surfaces:** desktop only (Electron bridge, native capture in forked child processes). Web shows the unavailable notice. No mobile or server part.
- **Where the code lives:** `apps/web/src/components/settings/SnapShotSettings.tsx` (617), `SnapShotSetupDialog.tsx` (541), `SnapShotSetupDialog.logic.ts`, `SnapShotSettings.logic.ts` (about 1k lines with tests across logic files), `CaptureShortcutConfig.tsx`, `useSnapShotShortcutRecorder.tsx`, `apps/web/src/lib/desktopSnapShot`.

## Problems today

- Heavy platform branching in logic files that must survive the rewrite intact.
- The browser build shows only a notice; there is no explanation of what SnapShots would do.

## Remodel goals

- **Experience:** the setup reads as a short checklist with live status per step (icon plus word), and the enabled page shows the current shortcut and backend in one line.
- **Motion:** setup steps use `sideBySide`; the capture flash and animation follow the MotionPolicy (reduced and off disable them, matching today's reduced-motion rule).

- [ ] "Finish later", picker-only mode and permission rechecks behave as today.
- [ ] Reduced and off motion disable the flash and animation.
- [ ] The web build explains the feature and that it needs the desktop app; dark and light.
