# E25-T11 · Storage and worktree cleanup

## What it is

The Storage page (`/settings/storage`) and the server job behind it. E6 Code creates **worktrees** (separate working directories with their own branch, one per thread in worktree mode), saves browser captures, and rotates logs; left alone these fill the disk. The page sets retention rules per machine (and worktree rules per project or checkout), and a background sweeper applies them. Every rule is off by default, so nothing is deleted until the user opts in.

## When it is used

- Disk is filling up with old worktrees from finished threads.
- A team wants merged or unchanged worktrees cleaned automatically, but one long-lived project must keep its worktrees.
- Browser captures or rotated logs should not be kept forever.

## How it works today

- **Entry points:** settings nav "Storage"; settings search ("Worktree cleanup" and each rule); docs under Settings → Storage.
- **Behaviour to preserve — every control:**

| Section            | Control                               | What it does                                                                                                                                                                                                                                       | Stored                                                                    |
| ------------------ | ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Worktrees          | Automatic worktree cleanup            | At project/checkout scope: Inherit, Off ("Keep this project's worktrees until you delete them manually") or Custom ("Use these rules for this project"); at machine scope it reflects each machine's rules; shows "Mixed across selected machines" | server, project-scopable (`worktreeCleanup`)                              |
| Worktrees          | Delete worktrees with deleted threads | Remove unused worktrees, including ignored files, when threads are deleted; uncommitted source changes are kept                                                                                                                                    | server (`storageCleanup.worktreeOnDelete`, or the project's custom rules) |
| Worktrees          | Delete inactive worktrees (days)      | Remove after threads are inactive N days; eligible archived sessions are stopped; branches and history kept                                                                                                                                        | server (`worktreeAfterDays`)                                              |
| Worktrees          | Delete merged worktrees               | When the PR is merged and commits are in the default branch                                                                                                                                                                                        | server (`worktreeOnMerge`)                                                |
| Worktrees          | Delete unchanged worktrees            | No commits beyond the default branch                                                                                                                                                                                                               | server (`worktreeUnchanged`)                                              |
| Artifacts and logs | Delete old browser artifacts (days)   | Older capture links stop opening                                                                                                                                                                                                                   | server (`browserArtifactsAfterDays`)                                      |
| Artifacts and logs | Delete old rotated logs (days)        | Current logs kept                                                                                                                                                                                                                                  | server (`logsAfterDays`)                                                  |

- **Server behaviour** (`storageCleanup.ts`, a reactor): runs at startup, hourly, and when triggered by a settings change, thread archive or delete, session stop and terminal exit. Resolves the policy per project (environment rules or project override). Only threads that are archived or ready, with no pending approval, no pending input, no running or queued turn, and no live terminal are eligible; it respects the workspace "in-use" lease; the inactivity clock ignores PR metadata refreshes. It never deletes uncommitted source changes silently.
- **Surfaces:** web and desktop page; server job. Mobile: no storage page for server cleanup (mobile's Client storage page is about its own cache, E34-T08).
- **Where the code lives:** `apps/web/src/components/settings/StorageSettings.tsx` (288), `packages/shared/src/projectSettings.ts` (`resolveWorktreeCleanup`), `packages/contracts/src/settings.ts` (`WorktreeCleanup`, `StorageCleanupSettings`), `apps/server/src/storageCleanup.ts` (573), `orchestration/ThreadSettlementPolicy.ts`, `workspace/workspaceLease.ts`.

## Problems today

- The user cannot see what the rules would remove or how much space they would free, and there is no "run now" or history of what was cleaned.
- Rules are destructive and live on each machine; at "All environments" scope a change fans out to every machine at once.

## Remodel goals

- **Experience:** show a preview ("3 worktrees, 2.1 GB would be removed now") and the last run's result per machine, with a manual "Clean up now" that respects the same guards. Destructive wording stays explicit about what is kept.
- **Performance:** the sweeper and any preview must not stall the event loop during streaming (server event-loop delay ≤ 20 ms p99).

## Done when

- [ ] Every control, scope behaviour (Inherit/Off/Custom, Mixed) and default-off rule is preserved.
- [ ] Server guards (eligibility, lease, live terminals, uncommitted changes kept) keep their tests; a new test covers any manual run.
- [ ] If preview or history is added, it is computed on the server per environment and labelled with the environment name.
- [ ] Dark and light; keyboard reachable; confirmations for any manual destructive action.
