# E25-T13 · Archived threads

## What it is

The Archive page (`/settings/archived`): every archived thread across the environments in scope, grouped by project, with a way to bring a thread back (Unarchive) or delete it permanently. Archiving hides a thread from the sidebar without deleting it; this page is the way back.

## When it is used

- Finding an old conversation that was archived from the sidebar.
- Restoring a thread to continue work on it.
- Deleting archived threads for good.

## How it works today

- **Entry points:** settings nav "Archive" (under Environment); settings search "archive"; mobile Settings → Archived Threads. Archiving itself happens in the sidebar and thread menus (E09-T03).
- **Behaviour to preserve:**
  - Threads are read from archived snapshots of every environment in the scope (`useArchivedThreadSnapshots(scope.environmentIds)`); at project or checkout scope only that project's members are shown.
  - One section per project (title and project favicon), rows with thread title and "Archived <relative time> · Created <relative time>", and an **Unarchive** button.
  - **Delete** is only available from the row's right-click context menu (Unarchive / Delete, destructive), and goes through the delete confirmation (respecting the "Delete confirmation" preference).
  - States: "Loading archived threads — Checking connected environments.", "Could not load archived threads" with the error, "No archived threads — Archived threads will appear here."; error toasts "Failed to unarchive thread", "Failed to delete thread", "Archived thread action failed". The list refreshes after each action.
- **Surfaces:** web and desktop. Mobile: `settings/archive` with environment filter, restore, delete, error and retry (`ArchivedThreadsScreen.tsx`, 462; E34-T05). Server: archive and unarchive commands and archived snapshots (`client-runtime/state/archivedThreads.ts`).
- **Where the code lives:** `apps/web/src/components/settings/SettingsPanels.tsx:3597-3819` (`ArchivedThreadsPanel`), `packages/client-runtime/src/state/archivedThreads.ts`, `useThreadActions`.

## Problems today

- Delete is hidden behind right-click: no visible control, no keyboard path, and no way on touch devices.
- No search, no bulk restore or bulk delete, no sort; a long archive is one long list. (Report 05 mentions a header bulk action; the current panel code has none.)
- Not virtualised.

## Remodel goals

- **Experience:** a searchable, multi-select list with visible Unarchive and Delete actions and an Undo after unarchive; restoring a thread shows where it went (the sidebar row). The reverse state of archiving is first class.
- **Motion:** a restored row leaves with `layout` (viewport only); the sidebar receives it without a second animation (one focal motion).
- **Performance:** virtualised list; the per-environment snapshot load does not block the page (rows appear per environment as they arrive).

## Done when

- [ ] Unarchive and Delete are both reachable by pointer, keyboard and touch, with the delete confirmation preference honoured.
- [ ] Grouping by project, scope filtering, relative times, loading, error and empty states preserved.
- [ ] Search and multi-select bulk actions added, or the owner decides against them.
- [ ] Virtualised; dark and light; keyboard reachable.
