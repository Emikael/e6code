# E25-T09 · Integrations: browser and devices

## What it is

The Integrations page (`/settings/integrations`): what agents may drive beyond the code (the in-app browser and simulators/emulators), and the defaults for the in-app browser preview on this device: profiles (cookie jars), viewport, zoom, appearance, recording options and where links open. It also manages SSH **device hosts**, remote machines that run simulators for the Device panel.

## When it is used

- Allowing or forbidding agents to use the in-app browser or devices, globally or for one project.
- Setting up a browser profile signed in to a staging site, or importing cookies from Chrome/Firefox/Safari.
- Choosing the default viewport and zoom the preview opens with, or recording settings for demos.
- Turning the device hub on, adding iOS/Android support, or adding an SSH device host.

## How it works today

- **Entry points:** settings nav "Integrations"; settings search (agent browser access, browser profiles, viewport, zoom, recording quality, where links open, floating preview, device rows); first use of the Device panel (setup wizard, E22-T02); "Check device tool versions".
- **Behaviour to preserve — every control:**

| Control                                | What it changes                                                                                                                                                                                      | Stored                                                |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| Agent browser access                   | Agents may drive the in-app browser                                                                                                                                                                  | server, project-scopable (`enableAgentBrowserAccess`) |
| Browser profiles                       | Create, rename, remove (confirm), set default; Incognito; Import from another browser (wizard: source browser, quit-browser prompt with recheck, data selection, imported-cookie approval, progress) | client (`browserProfiles`, `browserDefaultProfileId`) |
| Default browser viewport               | Fill, a preset, or custom width × height                                                                                                                                                             | client                                                |
| Default browser zoom                   | Zoom factor for new tabs                                                                                                                                                                             | client                                                |
| Default browser appearance             | Light, dark or system                                                                                                                                                                                | client                                                |
| Browser recording frame rate           | 30 or 60 fps                                                                                                                                                                                         | client                                                |
| Show key presses / mouse presses       | Overlays in recordings                                                                                                                                                                               | client                                                |
| Open links in                          | In-app browser or system browser (`browserLinkTarget`)                                                                                                                                               | client                                                |
| Auto-show floating preview             | Agent-opened browsers and devices float over the chat                                                                                                                                                | client                                                |
| Device hub, simulator/platform support | Turn the hub on; iOS/Android support with guidance to install a runtime or create an AVD                                                                                                             | server (`enableDeviceSupport`)                        |
| Agent device access                    | Agents get `device_*` tools; off hides them from new sessions                                                                                                                                        | server, project-scopable (`enableAgentDeviceAccess`)  |
| Device hosts                           | SSH alias or user@host, identity file, port; Test connection; Remove; fanned out across environments                                                                                                 | server (`deviceHosts`)                                |

- States: plain browser (browser rows rendered inside "Only available in the desktop app" and disabled), desktop, device support off/on, host connection checks running/passed/failed, simulator support absent.
- Imported cookies stay in the preview profile; agents use a separate profile; an agent driving a tab with imported cookies triggers Allow / Don't allow (E21-T03). Safari import needs Full Disk Access; Windows supports Firefox and Helium only.
- **Surfaces:** browser rows are desktop only; device rows work on web and desktop against the server. Mobile has "Agent browser access" under Server settings → Agent behavior (E34-T06). Server owns device hub and hosts.
- **Where the code lives:** `apps/web/src/components/settings/IntegrationsSettings.tsx` (1,464), `BrowserImportWizard.tsx` (603), `browserImportWizard.logic.ts`, `DeviceHostsSettings.tsx`, `DeviceHostEditor.tsx`, `deviceHostConnectionChecks.ts`, `useHostConnectionChecks.ts`, `importedCookieApprovalDialog.ts`.

## Problems today

- One 1,464-line file holds browser defaults, profiles and device settings.
- Device and browser preferences mix server rows (agent access, hosts) and device rows (preview defaults) under the same headings.

## Remodel goals

- **Experience:** split "What agents may use" (server, scoped) from "Preview defaults on this device"; the desktop-only group explains why in one sentence and links to the desktop app.
- **Motion:** the import wizard steps use `sideBySide`; host checks show words plus icons, no looping spinner without a label.

## Done when

- [ ] Every control in the table works with the same storage and scope, including project overrides of both agent access flags.
- [ ] The import wizard, approval prompt, and per-platform browser support rules are preserved.
- [ ] Device host add, test, remove and fan-out work; failures name the environment.
- [ ] Web shows the desktop-only state; dark and light; keyboard reachable.
