# E25-T12 · Background activity policy

## What it is

The **background activity policy** decides how much work an environment does when nobody is looking: how often it re-checks provider health, runs `git fetch`, samples host power, and whether it pauses on a locked host, low power or battery. Users choose a profile (Balanced, Performance, Battery saver) on General and can tune each interval in an Advanced dialog. On the server a shared policy applies these rules together with "demand" signals from connected clients (visible, focused, interacting) and the host's power state reported by the desktop app. This task also covers the **token streaming warning** dialog, the other dialog launched from General.

## When it is used

- A laptop running the server drains its battery or keeps fans spinning while idle.
- A user wants faster git status refreshes or provider health checks.
- Choosing "Token by token" response streaming, which triggers the warning.

## How it works today

- **Entry points:** General → Background activity select and its Advanced dialog; Providers → health check interval (Advanced section); Source Control → Git fetch interval; General → Response streaming → "Token by token". Server RPC `serverReportClientActivity`, `serverReportHostPowerState`, `serverGetBackgroundPolicy`, `subscribeBackgroundPolicy`.
- **Behaviour to preserve:**
  - **Profiles** (`packages/shared/src/backgroundActivitySettings.ts`):

| Setting                           | Performance  | Balanced (default) | Battery saver  |
| --------------------------------- | ------------ | ------------------ | -------------- |
| Git fetch interval                | 15 s         | default constant   | 0 (off)        |
| Provider health refresh           | 1 min        | default constant   | 15 min         |
| Host power monitor, active / idle | 30 s / 2 min | 30 s / 5 min       | 1 min / 10 min |
| Idle client TTL                   | 45 s         | 45 s               | 45 s           |
| Pause when host is locked         | on           | on                 | on             |
| Pause on host low power           | off          | on                 | on             |
| Pause on client low power         | off          | on                 | on             |
| Pause on battery                  | off          | off                | on             |

- **Advanced dialog** "Background Activity — Tune the shared power policy and the background intervals that feed it": profile select ("Shared background policy"), number fields in seconds for Git fetch, Provider health, Active host power and Idle host power intervals, and four switches (Pause when host is locked, Pause on host low power, Pause on client low power, Pause on battery). Values equal to the preset are normalised away so only real overrides are stored (`backgroundActivity: { schemaVersion: 1, profile, overrides }`); picking a profile clears overrides; reset restores the default. A legacy shape (top-level `automaticGitFetchInterval`, `providerHealthRefreshInterval`, `backgroundActivityProfile`) is still read.
- **Server policy** (`BackgroundPolicy.ts`): foreground client leases (45 s default, 120 s max, 16 leases per RPC client), visibility/focus/interaction, scopes (server-config, diagnostics, provider-status, vcs-status, git-refs, thread), host power from Electron (`HostPowerMonitor.ts`); exposes `hasDemand`, `shouldRunScopeWork`, `shouldRunOpportunisticWork` and a snapshot stream. Usage-limit hubs poll on the provider health interval (E28-T04).
- **Token streaming warning:** "Token by token is a worse experience — Token streaming repaints the message on every delta. It is slower, harder to read, and costs more CPU on every connected device…" with actions "Use token by token" (quiet), Cancel, and "Use paragraphs" (primary).
- **Surfaces:** web and desktop UI; server policy; desktop supplies power state; web and mobile report activity. Mobile edits Response streaming under Server settings → Agent behavior but has no background activity control (E34-T06).
- **Where the code lives:** `apps/web/src/components/settings/SettingsPanels.tsx:264-300` (overrides list, profile helpers), `:994-1290` (both dialogs), `packages/shared/src/backgroundActivitySettings.ts` (270), `apps/server/src/background/BackgroundPolicy.ts` (350), `background/HostPowerMonitor.ts` (101).

## Problems today

- The same intervals are editable in three places (General dialog, Providers, Source Control) with no indication that they are one policy.
- Users cannot see whether background work is currently paused, or why.
- Token streaming exists only for backwards compatibility and is an open removal question (architecture question 7).

## Remodel goals

- **Experience:** one place that shows the active profile, which work is paused right now and why (locked, battery, no client), with the per-task overrides; other pages link to it rather than duplicating controls.
- **Performance:** the policy exists to save CPU and battery; v2 clients must keep reporting activity leases accurately (a v2 screen that forgets to report visibility would keep work running, or stop it while visible).

## Done when

- [ ] All three profiles, every interval and switch, normalisation, legacy-shape reading and reset behave as today (tests ported).
- [ ] v2 clients report activity and visibility with the same lease rules; verified with the policy snapshot stream.
- [ ] Current paused/running state is visible in the UI with words and icons.
- [ ] The token streaming decision is recorded; if kept, the warning dialog is preserved.
- [ ] Dark and light; keyboard reachable.
