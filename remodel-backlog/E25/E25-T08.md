# E25-T08 · Source control settings

## What it is

The Source Control page (`/settings/source-control`): what version-control tools and code-hosting CLIs the environment found, whether they are signed in, how often git fetches in the background, and the defaults for pulling, merging and the commit and pull request text that agents write.

## When it is used

- After installing or signing in to a hosting CLI (`gh auth login`, `glab auth login`, `tea login add`, `az login`), to press **Rescan** and confirm E6 Code sees it.
- When a pull request action fails because no account is connected.
- Choosing the merge method, whether the default branch is pulled automatically, and how generated commit messages and PR descriptions are written.

## How it works today

- **Entry points:** settings nav "Source Control"; command palette navigates here from git-related actions; settings search (source control, git fetch interval, merge method, writing style, writer model); header **Rescan** button.
- **Behaviour to preserve — every control:**

| Control                         | What it does                                                                                                            | Stored                                                                                                                       |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Rescan                          | Re-detect VCS and hosting CLIs and their auth                                                                           | action                                                                                                                       |
| Version Control list            | git (and others) with status dot plus word, version, path                                                               | read-only                                                                                                                    |
| Source Control Providers list   | GitHub, GitLab, Bitbucket, Azure DevOps, Forgejo, Gitea with auth status and redacted account (`RedactedSensitiveText`) | read-only                                                                                                                    |
| Git fetch interval              | Background `git fetch` interval (a background-activity override, see E25-T12)                                           | server (`automaticGitFetchInterval`)                                                                                         |
| Automatically pull              | Fast-forward the default branch on clean checkouts                                                                      | server, project-scopable (`defaultAutoPull`)                                                                                 |
| Default merge method            | Merge, squash or rebase for PR merges                                                                                   | server, project-scopable (`pullRequestMergeMethod`); per-repository overrides are client (`pullRequestMergeMethodOverrides`) |
| Source control writing style    | Repository conventions, Conventional Commits, or Custom instructions                                                    | server, project-scopable, shared preference                                                                                  |
| Follow change request templates | Use the repository's PR template when generating descriptions                                                           | server (not verified whether project-scopable)                                                                               |
| Source control writer model     | Model for commit messages and PR text (falls back to the text generation model)                                         | server, project-scopable                                                                                                     |

- States: scanning skeleton, empty or error discovery, items not ready, Mixed values across environments.
- Credentials are configured outside the app (CLI logins; Bitbucket via `E6CODE_BITBUCKET_ACCESS_TOKEN` or email plus API token, needing a server restart).
- **Surfaces:** web and desktop. Mobile: Settings → Server settings → Source control (Automatically pull, Start from origin; E34-T06). GitHub sharing between environments is on Connections (E29-T09).
- **Where the code lives:** `apps/web/src/components/settings/SourceControlSettings.tsx` (503), `SourceControlWritingSettings.tsx`, `ProjectDefaultsSettings.tsx` (repositories category), `RedactedSensitiveText.tsx`; server source-control discovery in the VCS area (E23-T09).

## Problems today

- The page mixes read-only discovery (environment state) with project-scopable defaults, and discovery shows one environment while defaults fan out to the scope.
- Signing in requires leaving the app; the page explains status but not the command to run (docs do).

## Remodel goals

- **Experience:** each provider row shows its state as icon plus word and, when signed out, the exact command to sign in with a copy button; Rescan reports what changed.
- **Motion:** rescan uses a labelled stepped skeleton, never a looping spinner without text.

## Done when

- [ ] All rows and states in the table exist with the same storage and scope behaviour.
- [ ] Discovery states which environment it describes when the scope covers several.
- [ ] Sign-in guidance per host matches `docs/user/source-control.md`.
- [ ] Dark and light; keyboard reachable; status never shown by colour alone.
