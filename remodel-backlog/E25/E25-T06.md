# E25-T06 · Keybindings settings

## What it is

The Keybindings page (`/settings/keybindings`) and the model behind every keyboard shortcut in the web and desktop app. A **keybinding** is a rule `{ key, command, when }`: a key chord, one of a closed list of command ids, and an optional **when clause** (a condition such as `terminalFocus && !previewOpen`) that limits where the rule applies. Defaults ship with the app; a user's own rules live in `keybindings.json` on each environment and are merged on top, with the last matching rule winning. The same command registry feeds the command palette, menus and settings search.

## When it is used

- Rebinding a shortcut that clashes with a browser, the OS or muscle memory (for example `mod+w` and `mod+t` in a browser tab).
- Adding a shortcut for a command that has none (`thread.stop`, a project script `script.<id>.run`).
- Checking which key does what, or finding a command by its default key.
- Editing `keybindings.json` directly with "Open keybindings.json".

## How it works today

- **Entry points:** settings nav "Keybindings"; Cmd/Ctrl+F inside the page opens its search; settings search results for every command (by label, command id or default key) land on that command's first row; "Open keybindings.json" opens the file in the preferred editor; RPC `server.upsertKeybinding` / `server.removeKeybinding`; `keybindingsUpdated` on `subscribeServerConfig`; hand edits to `~/.e6/userdata/keybindings.json`.
- **Behaviour to preserve:**
  - Header: expandable search, binding count, "Add keybinding", "Open keybindings.json". A notice in browser (non-Electron) builds explains that some shortcuts are reserved by the browser.
  - Rows: one per (command, key, when) rule, with a source badge (Default, Custom, Project), a click-to-record key control, a when-clause control, and an overflow menu (Reset to default, Remove). Conflict warning when two rules match the same key in overlapping contexts; unknown-variable warning in a when clause. "Saving" state per command.
  - Recording: modifiers `mod` (Cmd on macOS, Ctrl elsewhere), `cmd/meta`, `ctrl/control`, `alt/option`, `shift`; platform `mod` handling is central to display and matching.
  - When-clause builder: AND/OR groups, negation, a variable select and a raw expression field. Context keys: `terminalFocus`, `terminalOpen`, `previewFocus`, `previewOpen`, `modelPickerOpen`, `editableFocus`, `isWeb`, `isDesktop`, plus custom variables; operators `!`, `&&`, `||`, parentheses.
  - New-binding row: command select, key input, when.
  - Commands: a closed list (`STATIC_KEYBINDING_COMMANDS`, 40+ ids covering workspace focus, sidebar, terminal, right panel, PR copy and merge, diff, preview, palette, composer pickers, chat new/newLocal, editor, model picker jump, thread jump/settle/pin/undo/stop/stopSubagent, theme select and appearance cycle, theme editor) plus generated families (`script.<id>.run`, thread jump 1–9, model-picker jump). Server defaults: 53 rules in `packages/shared/src/keybindings.ts`; new defaults are added on startup; invalid rules are ignored and reported as `issues`; a maximum rule count is enforced.
  - Documented reserved behaviour: on desktop `mod+w` closes the terminal or right-panel tab, then the window; in a browser rebind `rightPanel.close` and `terminal.close`; `mod+t` opens the right-panel new-tab menu; `mod+1`…`mod+9` jump to threads or models with an `isDesktop` condition.
  - States: no environment, no `keybindings.json` path, search jump clears the filter.
  - Writes fan out to every connected environment in the scope; only the representative environment supplies the displayed rows. Project-level overrides show the "Project" badge.
- **Surfaces:** web and desktop (desktop adds the native menu accelerators). Mobile does not use this model; it has hardware-keyboard commands of its own (Cmd+K palette, Cmd+1…9, Settings → Keyboard Return-key behaviour; E34-T05). Server: `Keybindings` service parses, validates, compiles when-expressions, caches the resolved config, watches the file.
- **Where the code lives:** `apps/web/src/components/settings/KeybindingsSettings.tsx` (1,595), `KeybindingsSettings.logic.ts` (359), `apps/web/src/keybindings.ts` (matching against `ShortcutMatchContext`), `packages/shared/src/keybindings.ts` (defaults, parser), `packages/contracts/src/keybindings.ts` (commands, when AST, rule schema), `apps/server/src/keybindings.ts` (685).

## Problems today

- One 1,595-line component; the list renders hundreds of rows with select and popover controls without virtualisation (`buildKeybindingRows` is memoised, the rendering is not).
- Edits fan out to all environments in scope but rows come from one environment, so differing files across machines are invisible.
- The command id list lives in contracts and must be kept in step with the web registry, the palette and the settings search by hand.
- There is no command to open Settings or Usage, so they cannot be bound (see E25-T01).

## Remodel goals

- **Experience:** a recorder that shows conflicts before saving and explains reserved browser shortcuts inline; a clear indication when environments hold different bindings.
- **Motion:** recording state and row changes are instant (3.10); the when-clause editor uses `pop`; a rejected chord uses `shake` with error text.
- **Performance:** the list is virtualised (shared list primitive) and filtering 70+ rules plus generated commands stays under one frame per keystroke.
