# E23-T09 · Git VCS driver and status broadcaster

## What it is

The server-side git engine and the stream that keeps every client's view of git current. The **VCS driver** runs git for status, refs, branch creation and switching, worktrees, staging and discard, pull, fetch and init, and supports checkpoint capture. The **status broadcaster** pushes each working directory's status to subscribed clients, refreshing remote state on a timer, and an **auto-pull** policy can fast-forward clean default-branch checkouts.

## When it is used

Constantly and invisibly: every branch label, ahead/behind count, changed-files badge, quick-action label (E23-T04) and diff panel depends on it. Auto-pull runs at server startup and on a schedule when enabled.

## How it works today

- **Entry points:** WS `vcsInit`, `vcsListRefs`, `vcsCreateRef`, `vcsSwitchRef`, `vcsCreateWorktree`, `vcsRemoveWorktree`, `vcsPull`, `vcsStage`, `vcsUnstage`, `vcsDiscard`, `vcsRestoreDiscard`, `vcsRefreshStatus`, and the stream `subscribeVcsStatus`; settings `defaultAutoPull` (default off) and per-project `projectAutoPullOverrides` ("Automatically pull default branch" in Settings → Source Control and per project); `autoPullProjects` in startup.
- **Behaviour to preserve:**
  - Status from `git status` porcelain v2 `-z`, split into a fast local half and a remote half with its own refresh cache; ahead/behind, upstream, ahead-of-default, working-tree changes, open PR summary, host kind.
  - Remote refresh every 30 s; failure backoff from 30 s up to 15 min with bounded diagnostics.
  - Background policy throttles `vcs-status` and `git-refs` scopes to foreground clients (E25-T12).
  - Refs listing with a snapshot cache, ahead/behind, pagination; worktree path per ref.
  - Ref names validated (`requireSafeRevision`, `requireBranchName`, `gitRefSafety.ts`).
  - Worktrees under `<E6 home>/worktrees`; create, remove, prune.
  - Discard keeps staged, ignored and nested repositories and can be restored (Undo) (user doc "Discard with Undo"); unavailable while the agent works.
  - Process limits: 8 concurrent git processes and 4 GitHub processes (`VcsProcess`), an inner semaphore of 8; default timeout 30 s; output capped at 1 MB with a "[truncated]" marker.
  - Auto-pull is fast-forward only and only on clean checkouts.
  - Git trace log watching; repository path resolution with caching.
  - Polling only: there is no filesystem watcher on working trees.
- **Surfaces:** server; consumed by web, desktop and mobile through `client-runtime` (`state/vcs.ts`).
- **Where the code lives:** `apps/server/src/vcs/GitVcsDriverCore.ts` (4,250 lines), `vcs/GitVcsDriver.ts` (1,245), `vcs/VcsProcess.ts`, `vcs/VcsDriverRegistry.ts` (abstraction for non-git VCS; only git exists), `vcs/VcsProjectConfig.ts`, `vcs/gitRefSafety.ts`, `vcs/VcsProvisioningService.ts`, `vcs/VcsStatusBroadcaster.ts` (738), `serverRuntimeStartup.ts` (`autoPullProjects`), `background/BackgroundPolicy.ts`.

## Problems today

- A 4,250-line core file with many subtle porcelain and ref parsing paths.
- Every status refresh spawns git processes; with several clients and many projects this is the server's main subprocess cost. Architecture 1.5 defers a native git read helper (gitoxide or a persistent `git cat-file --batch`) until CPU profiles show VCS polling.
- Polling without a watcher means changes appear up to one refresh late.
- The client also refreshes on window focus and menu open (E23-T04), adding requests on top of the broadcaster.

## Remodel goals

- **Performance:** measure spawns per minute per client and per project in the M0 harness; share one status computation per cwd across all subscribers (same pattern as the shell broadcaster, architecture 3.2 item 4); decide whether a watcher or the deferred native helper is worth it. Keep payloads small: status deltas, not full lists, on the stream.
- **Experience:** status freshness the user can trust: show "updated Ns ago" or a refresh affordance rather than stale ahead/behind counts.

## Done when

- [ ] Spawn rate and status latency measured and recorded against a budget (with E05).
- [ ] One status computation per cwd fans out to all subscribers.
