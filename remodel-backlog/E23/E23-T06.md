# E23-T06 · Default-branch protection

## What it is

A safety prompt shown before an action pushes to, or opens a PR from, the repository's **default branch** (usually `main`). It offers to continue on that branch, or to create an automatically named feature branch and run the same action there.

## When it is used

A local thread worked directly on `main` and the user clicks "Commit & push" or "Push & create PR".

## Current screen

No screenshot: the confirmation needs an action run on the default branch, and the demo repository was on a feature branch (listed in shots/gitpr/gaps.md).

In words: a dialog titled, for example, "Commit & push to default ref?" with "This action will commit and push changes on "main". You can continue on this ref or create a feature ref and run the same action there." Buttons: Abort, "Commit & push to main" (continue), and the primary "Check out feature branch & continue".

## How it works today

- **Entry points:** any Git actions run (quick action, menu, commit dialog) whose action is `push`, `create_pr`, `commit_push` or `commit_push_pr` while on the default ref (`requiresDefaultBranchConfirmation`). A plain `commit` on the default branch is **not** prompted.
- **Behaviour to preserve:**
  - Four copy variants (`resolveDefaultBranchActionDialogCopy`): push, commit & push, push & create PR, commit, push & create PR; host terminology (PR vs MR) in titles and labels.
  - The feature-branch path auto-names the branch (naming helpers in `@e6tools/shared/git`, server branch-name generation) and then runs the same action.
  - Abort leaves everything as is.
  - The commit dialog shows a "Default branch" tag on the branch row.
- **Surfaces:** web and desktop; mobile has an equivalent confirm sheet "Continue" vs "Feature branch & continue" (`GitConfirmSheet.tsx`, E33-T01).
- **Where the code lives:** `apps/web/src/components/GitActionsControl.tsx:2048–2088`, `GitActionsControl.logic.ts:312–375`.

## Problems today

- The epic summary describes this as a prompt "before committing"; it is in fact only before push or PR. Make that explicit in the redesign so the rule is intentional.
- Uses "ref" in user copy ("default ref", "feature ref") where users think "branch".

## Remodel goals

- **Experience:** plain wording ("You're on main"), the auto-generated branch name shown before confirming so the user knows what will be created, and the safer path as the focused primary action.
- **Motion:** standard dialog preset only.

## Done when

- [ ] The prompt fires for exactly the four actions above on the default branch, with tests.
- [ ] Feature-branch path shows the proposed name and runs the original action.
- [ ] Host terminology preserved; copy reviewed.
- [ ] Same rule and wording on mobile (shared view model in `client-runtime`).
- [ ] Dark and light, keyboard reachable (Escape aborts), reduced motion handled.
