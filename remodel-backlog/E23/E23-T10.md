# E23-T10 · Commit, PR and branch text generation

## What it is

One-shot AI calls the server makes to write **commit messages**, **pull request titles and descriptions**, and **branch names** (and thread titles, specified in E13-T17), using the user's own provider subscription. The user controls the model and the writing style in Settings → Source Control.

## When it is used

- A commit with an empty message (Git actions, commit dialog, diff panel commit box, mobile commit sheet).
- Creating a PR through a stacked action.
- Naming a new worktree's branch after the first turn, and naming an auto-created feature branch (E23-T06).

## How it works today

- **Entry points:** `TextGeneration` service methods `generateCommitMessage`, `generatePrContent`, `generateBranchName`, `generateThreadTitle`; called from `GitManager` (stacked actions) and from the provider command reactor (first-turn branch rename, thread titles). Settings: `textGenerationModelSelection` (default: the `codex` instance with the default text-generation model) and `sourceControlWritingStyle`.
- **Behaviour to preserve:**
  - Writing style modes: `repo_conventions` (default; "Repository conventions": follow the repository's existing history), `conventional_commits`, `custom` with `customInstructions`; `followChangeRequestTemplates` (default on) makes PR bodies follow the repository's PR template (`PrTemplateDetection.ts`).
  - Model comes from the text-generation selection or provider presets (`TextGenerationPresets.ts`), with policy in `TextGenerationPolicy.ts` and shared prompts in `TextGenerationPrompts.ts`.
  - Per provider: Codex (an `exec`-style helper), Claude (runs `claude -p --output-format json`; with "Claude verbose mode" it uses Claude Code's own configuration on the server; output wrapped differently in verbose mode), Cursor, Grok and Antigravity (ACP; Antigravity only when the profile has no hooks or MCP, per the E37-T11 matrix), OpenCode (through the shared owner server).
  - Claude has a 180 s timeout.
  - A failed generation must not leave the commit without a message; fallback behaviour not verified, check `GitManager`.
- **Surfaces:** server only; settings UI in E25-T08.
- **Where the code lives:** `apps/server/src/textGeneration/TextGeneration.ts`, `TextGenerationPrompts.ts` (329), `TextGenerationPolicy.ts`, `TextGenerationPresets.ts`, `ClaudeTextGeneration.ts`, `CodexTextGeneration.ts`, `CursorTextGeneration.ts`, `GrokTextGeneration.ts`, `OpenCodeTextGeneration.ts`, `AntigravityTextGeneration.ts` (six adapters, about 2k lines); `sourceControl/PrTemplateDetection.ts`; `packages/contracts/src/settings.ts:939–955`.

## Problems today

- Six separate adapters for one-shot generation, each with its own spawning and parsing.
- The user does not see which model wrote a message or how long generation took; a slow provider makes the whole stacked action look stuck.
- Inventory disagreement: report 06 (F-40) says Claude text generation uses the SDK; the code runs the `claude` CLI in print mode.

## Remodel goals

- **Experience:** generation is visible as its own phase in the stacked-action progress ("Writing commit message with Codex…"), and the result can be edited before push when the user chooses the dialog path.
- **Performance:** generation time recorded per provider; the stacked action reports a budget breach rather than hanging.

## Done when

- [ ] All three writing-style modes and template following covered by prompt tests.
- [ ] Each of the six providers has a recorded decision: supported, supported with limits, or not supported, aligned with E37-T11.
- [ ] Generation phase and model are visible in the progress UI (with E23-T04).
- [ ] Timeouts and failure fallback defined and tested.
