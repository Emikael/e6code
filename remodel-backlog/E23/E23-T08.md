# E23-T08 · Branch restore and PR thread dialogs

## What it is

Two small dialogs mounted by the thread view. The **branch restore confirmation** asks before switching the project checkout back to the branch a thread last ran on when there are uncommitted changes. The **pull request thread dialog** host (the dialog itself is specified in E24-T10) prepares a thread from a PR reference. Both share the thread's branch and PR link model.

## When it is used

- Restore: the branch-mismatch notice (E23-T01) says "Branch changed — was `feature-x`" and the user clicks **Restore branch** while the working tree has edits.
- PR thread dialog: the user typed a PR reference in the branch picker and chose "Checkout pull request".

## Current screen

No screenshot: the restore confirm needs a branch mismatch with uncommitted changes, and the PR thread dialog was not opened because it can prepare a checkout (see shots/gitpr/gaps.md).

In words: an alert dialog "Switch to `feature-x`?" with "You have uncommitted changes. They'll carry over to the other branch, or block the switch if they conflict." Buttons Cancel and "Switch branch".

## How it works today

- **Entry points:** Restore branch in the mismatch banner; the PR dialog opens via `openPullRequestDialog` in ChatView.
- **Behaviour to preserve:**
  - With a clean working tree, Restore switches immediately without the dialog; the confirm appears only when `hasWorkingTreeChanges`.
  - Switch runs `git switch` in the **project checkout** (`activeProjectCwd`), then, if the resulting branch differs from the thread's, writes `branch` and `worktreePath: null` to thread metadata.
  - Failure toasts: "Failed to switch checkout" and "Checkout switched, but the thread could not be updated" (partial success is reported, and status still refreshes).
  - The button shows "Restoring..." while running; composer focus returns afterwards.
  - The PR dialog is keyed per open so it remounts for each reference.
- **Surfaces:** web and desktop. Mobile: not verified.
- **Where the code lives:** `apps/web/src/components/ChatView.tsx:~6405–6470` (`handleSwitchCheckoutToThread`), `:6714` (`handleRestoreThreadBranch`), `:~11014–11060` (dialogs); `components/PullRequestThreadDialog.tsx`.

## Problems today

- Both dialogs and their handlers live in the 11k-line ChatView.
- The switch affects every local thread on the project, which the dialog does not say.

## Remodel goals

- **Experience:** the confirm names the consequence for other local threads and lists the changed files count; the action belongs to the strip's feature module, not ChatView.
- **Motion:** standard dialog preset.
