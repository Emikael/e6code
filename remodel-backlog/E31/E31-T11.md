# E31-T11 · Android-specific platform UX

## What it is

The Android app is not a reskinned iOS app: it has its own component set that follows Material Design 3 (buttons, icon buttons, switches, segmented controls, menus, dialogs, floating action buttons, search field), its own screen and sheet headers, Tabler icons in place of SF Symbols, and a set of native build plugins (predictive back, tablet orientation, modern popup menu and alert dialog themes, input background, cleartext traffic for LAN pairing, Gradle heap). This task owns that component layer and the Android-specific decisions, including whether Android icons move to the web's new icon set.

## When it is used

On every Android screen: headers, menus, dialogs, toggles and the New task button all come from this layer. Predictive back (Android 14+) shows the previous screen while swiping back. Tablets and foldables rotate freely.

## Current screen

No screenshot: mobile screens could not be captured in this environment (no simulator). Capture with `pnpm screenshots:mobile` on a Mac; see `docs/operations/mobile-app-store-screenshots.md`.

Layout in words: Android screens use `ScreenHeader.android` / `AndroidScreenHeader` (a Material top app bar with back arrow, title and subtitle, up to one direct action on phones and an overflow menu for the rest), `AndroidSheetHeader` for card-presented sheets, Material list rows, `MaterialSwitch`, `MaterialSegmentedControl` / `MaterialSegmentedButtons`, `MaterialButton`, `MaterialIconButton`, `MaterialRadioIndicator`, a Material search field, an extended floating action button for New task that shrinks on scroll, and popup menus anchored to their trigger through an overlay portal (`AndroidAnchoredMenu`, `MaterialMenuPopup`).

## How it works today

- **Entry points:** platform file suffixes (`*.android.tsx`) chosen by Metro; config plugins applied at native build time (`apps/mobile/plugins/*.cjs`); `AppSymbol` maps SF-Symbol-style names to Tabler icons on Android.
- **Behaviour to preserve:**
  - Thread header on phones shows one direct action (the inspector with its running-subagent badge, so the badge stays visible) and moves files, terminal and git into the overflow menu.
  - Sheets that iOS shows as form sheets render as full card pages on Android, because Android cannot host keyboard-driven form sheets (Settings, New task, review comment uses full-screen modal).
  - Material You dynamic colour on Android 12+ (E31-T06); Material dialogs with per-dialog destructive colour (E31-T07); Material date/time dialog for Custom snooze (E31-T03).
  - Predictive back compatibility, free tablet orientation, modern popup-menu and alert-dialog themes, input background styling, cleartext HTTP allowed for LAN pairing, Android notification icon and adaptive launcher icons.
  - Tabler icons are imported one by one ("to avoid registering the full set in Metro"); the PR glyph uses Tabler on iOS as well.
  - No composer layout animation on Android, and Android keyboard handling uses `KeyboardStickyView` (E32-T03).
- **Platform differences:** this task is the Android side; iOS counterparts are Liquid Glass headers, native toolbars, SF Symbols (`expo-symbols`) and native sheets.
- **Surfaces:** mobile (Android). No web counterpart; the shared registry of semantic icon names (architecture 2.5, E03-T01) is the link to web.
- **Where the code lives:** `apps/mobile/src/components/Material*.tsx`, `AndroidAnchoredMenu.tsx`, `AndroidScreenHeader.tsx`, `ScreenHeader.android.tsx`, `ScreenHeaderButton.android.tsx`, `ControlPillMenu.android.tsx`, `OverlayPortal.tsx`, `headerMenu.android.ts`, `useMaterialToolbarHeight.ts`, `AppSymbol.tsx`, `AppSymbol.tabler.d.ts`; `apps/mobile/plugins/withAndroid*.cjs`; `modules/e6-native-controls/android`.

## Problems today

- A duplicate component set: many primitives exist twice (iOS and Android) with separate behaviour and bugs.
- Icons: Android uses Tabler, iOS SF Symbols, web Lucide (to be replaced); the same concept can look different on each.

## Remodel goals

- **Experience:** Android stays Material You (design direction §8), but its primitives are built from the shared tokens (planes, roles, radii, type scale) so a status reads the same on Android, iOS and web. If decision D2b is approved, Android icons move from Tabler to the Phosphor artwork through the shared semantic registry; iOS keeps SF Symbols.
- **Motion:** Material motion durations mapped to the shared motion tokens (E02-T04); predictive back keeps working with custom transitions.
- **Performance:** keep per-icon imports (or generated components) so the icon set is never registered in full.

## Done when

- [ ] Every Material primitive listed above exists in the new design system with tokens applied, light and dark, Material You on and off.
- [ ] Icon decision D2b recorded; `AppSymbol` resolves through the shared semantic registry on Android.
- [ ] Predictive back, tablet orientation and LAN cleartext pairing verified on Android 14+ and a tablet.
- [ ] TalkBack labels and 48 dp touch targets on every primitive.
- [ ] Config plugins still apply after the rebuild (native client builds through `scripts/mobile-native-client.ts`).
