# E26-T06 · Typography and fonts

## What it is

Typography settings let a user choose the fonts and sizes E6 Code uses on this device: an interface font, a prompt (composer) font, a code font and a terminal font, each with a size, plus word wrap and, on macOS, font smoothing. Geist and Geist Mono are bundled and used by default; any installed system font can be chosen instead. A Simple mode uses one monospace font for code and terminal; Advanced separates them.

## When it is used

- A user who reads code all day sets their usual editor font (for example JetBrains Mono) for code and terminal.
- A user with low vision raises the interface size, or a user on a small laptop lowers it.
- A user turns word wrap on so long lines in code blocks, tables, diffs and file previews wrap instead of scrolling.

## How it works today

- **Entry points:** Settings → Appearance → Reading and Typography; settings search anchors for each row. The font picker dropdown could not be photographed (no local fonts in the headless capture browser).
- **Controls and storage** (client settings, per device):

| Control                                                                                  | Range / default                    | Key                                       |
| ---------------------------------------------------------------------------------------- | ---------------------------------- | ----------------------------------------- |
| Interface font, size                                                                     | size 12 to 20, default 16          | `fontFamilySans`, `fontSizeInterface`     |
| Prompt font, size (Advanced)                                                             | size 12 to 20, default 14          | `fontFamilyComposer`, `fontSizePrompt`    |
| Code font, size (Simple mode labels it "Monospace font" and it also drives the terminal) | size 10 to 18, default 13          | `fontFamilyCode`, `fontSizeCode`          |
| Terminal font, size (Advanced)                                                           | size 8 to 20, default 12           | `fontFamilyTerminal`, `fontSizeTerminal`  |
| Font smoothing                                                                           | macOS only                         | `fontSmoothing`                           |
| Word wrap                                                                                | code, tables, diffs, file previews | `wordWrap`                                |
| Simple / Advanced typography                                                             | per device, not a setting          | localStorage `e6code:typography-advanced` |

- **Behaviour to preserve:**
  - Font family values are strings up to 200 characters; empty means the default.
  - A custom family is always prepended to the default stack, so a missing font falls back to Geist / Geist Mono.
  - Code and terminal fonts must be monospace; the picker enforces it.
  - The picker enumerates local fonts (Local Font Access where available) in a virtualised list (`@legendapp/list`, the only virtualised list in settings); the text input commits only after typing pauses and the typed name probes as available.
  - The interface size scales every rem-based dimension in the app, which is why its range is narrow.
  - Live previews show the prompt, a diff and a terminal snippet in the chosen fonts.
  - Mobile has its own text, markdown, code and terminal size controls (E31-T06) and no font family choice.
- **Surfaces:** web and desktop.
- **Where the code lives:** `apps/web/src/appearanceFonts.ts` (395 lines), `components/settings/FontFamilyPicker.tsx` (249), `SettingsFontPreviews.tsx` (272), `SettingsPanels.tsx` lines about 1715-2250, `packages/contracts/src/settings.ts` (ranges and defaults).

## Problems today

- The picker's probe-and-debounce input is subtle: typed names that do not probe as installed silently never commit.
- Simple vs Advanced is device-local UI state outside client settings, so restoring defaults does not reset it.
- Local font enumeration requires a permission in some browsers; the denied state is not described in the inventory (not verified).

## Remodel goals

- **Experience:** sizes map onto the v2 type scale (`--text-*`, design direction §4.3) so changing interface size or font scales every v2 text style; monospace stays reserved for code, paths, IDs, key hints and diff stats.
- **Performance:** loading or probing fonts never blocks first paint; Geist faces are preloaded for the boot shell with size-adjusted fallbacks so a stored custom font does not cause a visible layout shift on start (E01-T12 "Typography system and font loading").
- **Motion:** none beyond the standard menu preset for the picker; previews update instantly.

## Done when

- [ ] All controls, ranges, defaults and keys above are preserved, including the monospace rule and stack prepending.
- [ ] Changing interface font or size updates every v2 text style without reload.
- [ ] Font enumeration denied or unsupported shows a typed-name fallback with a clear "not found on this device" state.
- [ ] Cold start with a custom interface font shows no layout shift (recording).
- [ ] The picker is keyboard operable and reviewed in dark and light.
