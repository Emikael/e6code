# E26-T01 · Appearance settings and runtime sync

## What it is

Settings → Appearance is where a person sets how E6 Code looks on this device: light, dark or "Match system", which theme to wear in each half, the accent colour, chat width, contrast, glass opacity, diff colours, how reasoning effort is drawn, the thinking timeline and the panel animation speed. It also includes the code that applies those choices to the whole document as CSS state the moment they change. All of it is per device: nothing on this page is written to a server.

## When it is used

- First day: a user switches to dark, picks a built-in theme (E6 Chat, Grove, Ocean, Ember, Iris) or an accent for the stock theme.
- Readability: a user on a large monitor sets Chat width to Wide or Full, raises Contrast, or switches diffs to blue-orange because they cannot tell red from green.
- Comfort: a user turns panel animations off, or lowers glass opacity because translucent menus are hard to read.
- Every app start: the runtime sync applies the stored values before the first paint so the app does not flash the wrong theme.

## How it works today

- **Entry points:** settings nav "Appearance" (`/settings/appearance`, a "device only" page, so the machine/project scope breadcrumb is hidden); settings search (each row has an anchor such as `#theme`); command palette "Change theme" and "Change appearance"; keybindings `theme.select` (Cmd+Option+A / Ctrl+Alt+A opens the picker) and `appearance.cycle` (Cmd+Option+Shift+A / Ctrl+Alt+Shift+A cycles System, Light, Dark); "Restore device defaults" on General also resets appearance and theme state.
- **Page layout, top to bottom:** Theme (three radio cards with wireframe previews: Light, Dark, Match system; each card shows the theme assigned to that half), Accent chips (stock theme only), the theme library "More themes" (built-in cards, custom theme collections, environment-published themes, "Create theme", "Add theme"; detailed in E26-T02 to T05), Reading (interface font, chat width, thinking timeline), Typography (E26-T06), Advanced, Motion.
- **Controls and storage** (all client settings in `ClientSettingsSchema`, `packages/contracts/src/settings.ts`, unless noted):

| Control                    | Values                                                                                                    | Stored                                                |
| -------------------------- | --------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| Appearance mode            | Light / Dark / Match system                                                                               | localStorage `e6code:theme-appearance-mode`           |
| Theme per half             | any library theme                                                                                         | localStorage `e6code:theme`, `e6code:theme-halves:v1` |
| Accent                     | Iris (default), Cobalt, Rose, Graphite; stock theme only, disabled otherwise                              | `stockAccent`                                         |
| Chat width                 | `comfortable` (default), `wide`, `full` (docs call them Standard/Wide/Full; only matters on wide screens) | `chatWidth`                                           |
| Show the thinking timeline | on by default; a malformed stored value decodes as on                                                     | `showThinkingTimeline`                                |
| Contrast                   | slider 50 to 200, default 100; above 100 boosts                                                           | `appearanceContrast`                                  |
| Glass opacity              | slider, max 100, default 80; affects menus, dialogs, composer                                             | `glassOpacity`                                        |
| Environment identification | `artwork` (default), `pill`, `none`; Dev/Nightly marker, row only shown when the build has a stage label  | `environmentIdentificationMode`                       |
| Diff colors                | `red-green` or `blue-orange`                                                                              | `diffColorScheme`                                     |
| Effort display             | `label` (e.g. "High") or `bars` in the composer                                                           | `effortDisplay`                                       |
| Panel animations           | slider 0 to 400 ms, default 0 (off), with a live preview; respects OS reduced motion                      | `panelAnimationDurationMs`                            |

- **Runtime sync** (`routes/__root.tsx:260-340`): applies contrast (three CSS variables `--appearance-contrast-base/boost/border-boost` from `appearanceContrast.ts`), diff colour scheme, chat width, stock accent (`stockAccent.ts`), glass opacity and blur, font families, sizes and smoothing, the environment-published palette, default-theme adoption (E26-T05) and the browser chrome `theme-color`. The `index.html` boot script applies the stored theme before React loads and must stay in sync with these rules.
- **Behaviour to preserve:**
  - Every change applies live, with no save button and no reload.
  - Accent applies only to the stock E6 Code theme; with another theme active the chips are disabled, not hidden.
  - Light and dark halves can hold different themes; "Match system" follows the OS live.
  - Single-appearance themes (a custom theme with only a dark variant) and light/dark pairs both work in the cards.
  - Panel animations default to off and are suppressed under OS reduced motion.
  - The Environment identification row is hidden when the build has no stage label.
  - Storage errors (blocked localStorage) are handled explicitly; a failed theme restore shows its own toast.
  - Desktop: theme changes also recolour the native window (background, title bar overlay) through the desktop bridge (`resolveDesktopTheme`, see E30-T01).
  - Mobile has its own Appearance screen (color scheme, themes incl. Material You on Android, accent, text sizes, thinking timeline) reading the same shared palettes (E31-T06); it does not share stored values with web.
- **Surfaces:** web and desktop (same page); mobile separate screen (E31-T06); no server involvement except environment themes and `defaultTheme` (E26-T05).
- **Where the code lives:** `apps/web/src/components/settings/SettingsPanels.tsx` (3,819 lines; `AppearanceSettingsPanel` at about line 1300, sliders about 1420-1700), `ThemeSettings.tsx` (1,055; `AppearanceModeCards`, `ThemeLibrary`), `StockAccentSetting.tsx`, `PanelAnimationsPreview.tsx`, `ThemeWireframe.tsx`, `ThemePreviewCircles.tsx`, `apps/web/src/appearanceContrast.ts`, `stockAccent.ts`, `hooks/useTheme.ts` (679), `routes/__root.tsx`, `apps/web/index.html` (boot script).

## Problems today

- The panel lives inside a 3,819-line file shared with General, Archive and About.
- Three sliders each hand-build CSS-variable styling for the filled track.
- The runtime sync is spread across the root route, several hooks and the boot script; the boot script is a hand-maintained copy of the theme rules (architecture 2.6).
- Panel animation duration is a single number for one kind of motion; there is no app-wide motion setting.
- Glass opacity exists as a style knob, while the design direction rations blur to small floating planes.

## Remodel goals

- **Experience:** keep the page calm and dense (design direction §8 "Settings is the equipment rack"). Theme cards become live miniatures rendered with the real v2 primitives, including the key light, in both halves. Section switches are cuts.
- **Motion setting:** replace `panelAnimationDurationMs` with the Motion control (Follow system, Full, Reduced, Off) that feeds MotionPolicy, plus the "Change motion" palette entry (design direction §5.6; the control itself is specified in E02-T06). Decide how a stored `panelAnimationDurationMs` maps to the new levels.
- **Glass and contrast:** decide whether Glass opacity survives now that blur is a fixed material on small floating planes and turns opaque under "Reduced"; Contrast must act on the new plane and edge tokens, not only on today's three variables.
- **Motion:** changing theme or appearance is an instant swap of tokens (no cross-fade of the whole app); the only motion on the page is the card selection indicator (`spring.snappy`) and slider thumbs.
- **Performance:** applying a theme must not cause more than one style recalculation; the boot script and Electron background are generated from the token pipeline so the first frame matches (desktop first themed paint ≤ 300 ms).
