# E26-T04 · Theme import (JSON, VS Code, Open VSX)

## What it is

"Add theme" installs themes that someone else made. It accepts an E6 Code theme file (JSON), a VS Code colour theme file, or a VS Code extension found on Open VSX (the open registry of VS Code extensions), searched and downloaded from inside the dialog. VS Code themes are converted into an E6 palette: the importer derives a full, readable palette from the theme's editor background and accent and then layers the theme's own workbench colours on top. Light and dark variants from the same extension are paired into one library entry.

## When it is used

- A user already lives in Dracula, Catppuccin, Nord or Tokyo Night in their editor and wants E6 Code to match.
- A teammate sends an exported `.json` theme from E26-T03.
- A user drops several theme files at once (for example a family of variants).
- A user re-imports an updated version of a theme they already installed.

## How it works today

- **Entry points:** Appearance → theme library → "Add theme"; drag files onto the drop zone; "Choose files" (desktop uses the native picker via `desktopBridge.pickThemeFiles`, browser uses a file input); paste JSON into the textarea; search Open VSX in the dialog.
- **Dialog contents:** a drop zone and a syntax-highlighted JSON textarea (highlighting is skipped above 20,000 characters); file size limit 256 KB per theme file with a plain-language error ("Theme files are only a few KB…"); a **conflict step** when an imported id is already installed: "update the existing theme" or "add a copy" (copies are named "Name (1)", "Name (2)"… up to 99); a "Search Open VSX themes" block with suggested searches and sort by downloads, rating, newest or relevance.
- **Open VSX import** (`openVsxThemes.ts`, 776 lines): queries `open-vsx.org` from the browser, downloads the VSIX and unzips it in the browser with JSZip, reads `package.json` contributes, resolves `include` chains, parses JSONC (`jsonc-parser`). Hard limits: VSIX 20 MB, search response 512 KB, detail and manifest 256 KB, theme file 256 KB, 5,000 zip entries, 100 MB uncompressed, compression ratio 200, 40 themes per extension, include depth 8, path length 1,024, colour value length 128. Only extensions whose manifest licence matches one of 0BSD, Apache-2.0, BSD-2-Clause, BSD-3-Clause, CC0-1.0, ISC, MIT, MPL-2.0, Unlicense are offered. `@noble/hashes` is also used (purpose not verified; likely integrity).
- **VS Code conversion** (`vscodeThemeImport.ts`, 454 lines): derives a contrast-solved base palette from `editor.background` and the accent, then overlays a fixed set of workbench colours (`activityBar.background`, `panel.border`, `contrastBorder`, …); a foreground candidate is accepted only if it reaches 4.5:1 against its surface, otherwise the derived value is kept; pairs light and dark variants; resolves label collisions.
- **E6 theme files:** parsed leniently (`parseThemeFile`), version must equal `THEME_FILE_VERSION` (1) or the user sees "This theme file uses an unsupported version".
- **Behaviour to preserve:**
  - Multi-file import in one go; partial success reports which files failed and why.
  - Conflict step with update vs copy, applied to every conflicting theme in the batch.
  - All size, count, ratio and depth limits, and the licence allowlist; these are security measures (report 05 F-7).
  - Imported themes never take a reserved id.
  - Unreadable foregrounds fall back to derived values rather than being imported as-is.
  - Offline or `open-vsx.org` unreachable: search shows an error; file and paste import still work.
- **Surfaces:** web and desktop (desktop adds the native file picker). Not on mobile.
- **Where the code lives:** `apps/web/src/components/settings/ThemeImportDialog.tsx` (561 lines), `ThemeSearchSection.tsx` (459), `apps/web/src/openVsxThemes.ts` (776), `apps/web/src/vscodeThemeImport.ts` (454), `apps/web/src/themePalette.ts` (`parseThemeFile`, `installCustomTheme`, `replaceCustomThemeCollection`).

## Problems today

- Network calls to a third-party registry and zip parsing run on the main thread in the browser; a large VSIX can stall input (not measured).
- The importer maps onto today's roles only; it knows nothing about planes, so imported themes inherit the "all panels at one brightness" look.
- Results without a supported SPDX licence are silently dropped; users do not learn why a theme they know is missing.

## Remodel goals

- **Existing imports:** themes already imported keep working unchanged; they gain plane and light roles from the derivation in E26-T02. The converter may additionally map VS Code's `sideBar.background`, `editorWidget.background` and similar onto plane overrides, but only as optional overrides.
- **Experience:** search results show a live miniature of each theme (light and dark) before download; excluded-licence results are explained in one line. Import ends with the new theme selected and a one-tap "Undo".
- **Performance:** VSIX download, unzip and conversion run in a worker so the UI stays inside the input-latency budget; the JSZip and parser code stays in a lazy chunk loaded only when the dialog opens (bundle budget: other routes ≤ 150 KB incremental).
- **Motion:** dialog uses the standard dialog preset; the conflict step slides with `sideBySide`.
