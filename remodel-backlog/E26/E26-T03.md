# E26-T03 · Theme editor

## What it is

The theme editor lets a user build or change a custom theme while looking at the real app. It is a floating, draggable panel that stays open over any screen: you name the theme, pick Light or Dark, choose a few seed colours (Guided) or edit every colour role (Advanced), and see the whole app repaint as you go. An **inspector** lets you point at any element in the app to find which colour role paints it. Custom themes are saved in a local library where they can be used, duplicated, edited, exported as a JSON file and removed.

## When it is used

- A user wants their own look: starts from "Create theme" and tunes background and accent.
- A user likes a built-in or imported theme but wants one colour changed: Duplicate, then Edit.
- A user sees an element with poor contrast and uses the inspector to find its role.
- A user shares a theme with a teammate or publishes it to a server (E26-T05) via Export.

## How it works today

- **Entry points:** Appearance → "Create theme"; Edit or Duplicate on a theme card; keybinding `themeEditor.toggle` (default `mod+alt+shift+t`, no `when` clause); command palette (theme editor toggle, owned by E10-T03). The editor host (`ThemeEditorHost`) is mounted app-wide, so the panel stays open when the user navigates to the chat or any other screen.
- **Panel:** draggable, resizable, minimisable. Fields: Name; Light/Dark switch (which variant you are editing); Guided mode with a few seed colours (Background, Accent and a generated palette, `createVividThemeColors`); Advanced mode with grouped role families (Background, Surface, Raised surface, Overlay, Text, Muted text, Border, Input, Subtle and Highlight surfaces, Accent, Action, Message surface, Code surface, Sidebar background/controls/selection, Terminal background, Error, Warning, Merged) and a filter field; a colour picker per role (`ThemeColorPicker.tsx`); Inspect; Save (or "Create theme") and Cancel.
- **Inspector:** while active, hovering any element highlights it and shows which roles colour it with a usage count; clicking selects the role in the panel. A throttled MutationObserver refreshes the spotlight as the DOM changes.
- **Live preview:** the draft is applied to the real UI under a reserved id `__preview` (`applyThemeColorPreview`); Cancel restores the previous theme.
- **Library actions** (on custom cards): Use, Duplicate, Edit, Export file (versioned JSON, `serializeThemeFile`, `THEME_FILE_VERSION = 1`), Remove. Custom themes are stored in localStorage `e6code:themes:v1` as light and/or dark colour maps, optionally grouped into a `collection`. A theme built in Guided mode is marked `managed` so it can regenerate from its seeds.
- **Behaviour to preserve:**
  - New vs editing vs duplicating a built-in, an import or an environment theme (duplicate makes an editable local copy; environment themes cannot be edited in place).
  - Editing one half does not drop the other half.
  - Dirty and invalid draft states; Cancel discards and restores; names map to ids (`themeIdFromName`) that never collide with reserved ids.
  - Inspector can be toggled off; Escape leaves inspect mode before closing the panel (not verified).
  - Panel position and size are kept only for the session.
  - Custom themes are per device; they are not synced, except by publishing a file on a server.
- **Surfaces:** web and desktop. Mobile has no editor; it can wear published themes only (not verified for custom).
- **Where the code lives:** `apps/web/src/components/settings/ThemeEditorPanel.tsx` (1,310 lines; panel at about line 278, inspector refresh at 565-621), `ThemeEditorHost.tsx`, `themeEditorStore.ts` (zustand), `themeInspector.ts` (504), `ThemeColorPicker.tsx` (371), `apps/web/src/themePalette.ts` (`installCustomTheme`, `updateCustomTheme`, `removeCustomTheme`, `parseThemeFile`, `serializeThemeFile`), `hooks/useCustomThemes.ts`, `ThemeSettings.tsx`.

## Problems today

- Advanced mode shows about 60 colour pickers at once.
- The inspector observes DOM mutations for as long as it is open (throttled, but still work on every streamed row).
- Panel size and position are local component state, lost on reload.
- No preview of contrast problems: a user can save a theme with unreadable text.

## Remodel goals

- **Experience:** Guided mode is the front door: background, accent and an optional "planes" depth slider produce a complete theme including the derived plane and light roles; the editor shows a preview of the key light (design direction §4.1 "Themes"). Advanced groups roles by what the user sees (planes, text, accent, status, terminal) and flags each pair below 4.5:1 with a word and icon, not colour alone.
- **Existing custom themes:** every theme in `e6code:themes:v1` opens in the v2 editor unchanged. Derived roles show as "derived" and only become stored overrides when the user changes them, so saving an old theme without touching new roles writes the same data back.
- **Motion:** the floating panel uses the `pop` preset on open and `quick` exit; the inspector spotlight follows the pointer instantly (no tween). Colour changes apply immediately.
- **Performance:** the inspector does no work while the pointer is still and stops observing when inspect mode is off; editing a colour costs one variable write, not a re-render of the panel.
