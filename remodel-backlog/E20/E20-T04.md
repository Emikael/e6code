# E20-T04 · Terminal manager (PTY) on the server

## What it is

The server side of terminals: the terminal manager that owns every PTY (pseudo-terminal) for every thread on an environment. It opens and attaches sessions, streams output to any number of clients, writes input, resizes, clears, restarts and closes them, reports what is running inside each one, and keeps a bounded, restart-safe scrollback history (5,000 lines and 8 MiB per terminal). Because the server owns the PTYs, a terminal keeps running when the browser reloads, and a phone can attach to the same shell the desktop started.

## When it is used

- Every terminal on every client, including the desktop renderer, which also attaches through the environment connection.
- Project scripts, worktree setup scripts and provider install/sign-in commands that run in terminals.
- Reconnecting after a network drop or a server restart: history is restored from disk.

## Current screen

No screenshot: server component. Its effects are visible in the terminal drawer and panel (E20-T01) and on mobile (E33-T04).

## How it works today

- **Entry points:** WebSocket RPCs `terminal.open`, `terminal.attach` (stream), `terminal.write`, `terminal.resize`, `terminal.clear`, `terminal.restart`, `terminal.close`; subscriptions `subscribeTerminalEvents`, `subscribeTerminalMetadata`; setup scripts (`07:F-32`); storage cleanup.
- **Behaviour to preserve:**
  - **History retention (user docs):** up to 5,000 lines and 8 MiB of UTF-8 per terminal; the oldest output is removed when either limit is reached, a long line can be shortened at its start, new output is never truncated; limits apply on reconnect and restore; a client may show less than the server keeps.
  - **Incremental history:** PTY callbacks append chunks and live events carry only new chunks; never copy the full scrollback per callback. Persistence is debounced (40 ms), chunked (16 KiB) and reads the latest buffer when the write runs. Eviction never splits a Unicode code point and releases chunk references immediately.
  - **Lifecycle boundaries:** clear, restart and close drain pending writes first.
  - **Restore:** reads only the bounded tail of current or legacy history files, skips an incomplete UTF-8 prefix, applies the line limit, and closes the read handle before rewriting the capped file.
  - **Reply stripping:** terminal query/response traffic is stripped from stored history so replay cannot provoke new replies at the prompt.
  - **Shell selection** with fallbacks; AppImage environment scrubbing; provider-aware environment (separate Codex and Claude homes).
  - **Metadata:** running subprocess, child command label and process ids; detection of listening ports per terminal (via the port scanner). Subprocess inspection polls `ps -eo pid=,ppid=,comm=` every 1 s (backoff up to 60 s on failure, 512 KiB output cap, 1 s timeout, a truncated table is rejected; `ps` resolved to an absolute path once), or uses the resource monitor's process table when available.
  - Up to 128 retained inactive sessions; kill grace of 1 s.
- **Surfaces:** server; consumed by web/desktop (Ghostty WASM) and mobile (native libghostty).
- **Where the code lives:** `apps/server/src/terminal/Manager.ts` (3068 lines), `terminal/NodePtyAdapter.ts` (189), `terminal/PtyAdapter.ts`, `terminal/OutputProtocol.ts`, `docs/internals/terminal-runtime.md`, `docs/user/terminal.md`; native addon `node-pty`.

## Problems today

- 1 s `ps` polling per terminal manager costs idle CPU and battery while terminals are open (architecture §3.2 item 9).
- `Manager.ts` is a 3068-line file; the history and retention rules are subtle and documented only in `terminal-runtime.md`.

## Remodel goals

- **Performance:** replace `ps` polling with the resource monitor v4 process-tree and listening-socket queries (architecture §1.5 item 1), keeping `ps` as the fallback. Keep incremental history and the retention caps; measure throughput with full scrollback when touching this path. Terminal output frames must stay within the live-frame payload budget (no frame over 256 KiB, architecture §3.1).
- **Experience:** none user-visible beyond faster, quieter idle; the contract with clients is unchanged.

## Done when

- [ ] Retention, restore, reply stripping, drain-before-lifecycle and session limits keep their behaviour, with the existing tests green and a throughput benchmark with full scrollback recorded.
- [ ] With the native monitor present, no `ps` processes are spawned during a 10-minute idle terminal session; labels and port hints match the fallback.
- [ ] Wire contract unchanged (or changed additively, gated by capability).
- [ ] `docs/internals/terminal-runtime.md` updated only if a documented constraint changes.
