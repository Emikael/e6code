# E20-T02 · Ghostty terminal engine

## What it is

The web terminal renders with E6 Code's own engine, not xterm.js: the official `libghostty-vt` terminal core compiled to WebAssembly, with a Canvas 2D renderer and a browser surface that handles keyboard input, IME, selection, scrolling, sizing, link detection and cursor blinking. Android uses the same `libghostty-vt` C ABI natively, so terminal behaviour (escape sequences, wrapping, Unicode) matches across clients. This task is the engine as a foundation: it is kept, not replaced; the work is wrapping it in the v2 terminal UI cleanly and protecting its rules.

## When it is used

Every time a terminal is visible on web or desktop (drawer or panel), and indirectly whenever a terminal's output is replayed after a reconnect.

## Current screen

No screenshot of its own: the engine is the canvas inside the terminal drawer and panel (see E20-T01).

## How it works today

- **Entry points:** used by `ThreadTerminalDrawer`'s `TerminalViewport`; no user-facing controls of its own.
- **Behaviour to preserve:**
  - **One WASM instance per browser tab** (`runtime.ts`), shared by all terminals; each terminal owns and frees its own Ghostty handles (`core.ts`).
  - **Rendering:** `renderer.ts` batches backgrounds and style runs into a Canvas 2D frame; `surface.ts` owns the render loop. No React state in the render loop (README rule).
  - **Input:** keyboard mapping (`keyCodes.ts`), IME composition, paste, selection, wheel and scrollback scrolling, resize to cell grid, cursor blinking.
  - **Links:** URL and file-path detection across wrapped lines (E20-T03 handles activation).
  - **Fonts:** the symbols-only Nerd Font is vendored and registered lazily, so prompt glyphs render without a local Nerd Font.
  - **Theme:** colours come from the app's CSS variables (terminal roles).
  - **Replay safety:** while replaying retained history, the renderer detaches its PTY writer so historical device queries do not produce fresh replies at the prompt (paired with server-side stripping, E20-T04).
  - **PTY replies:** a 112-byte `ghostty-write-pty.wasm` trampoline forwards terminal-generated replies.
  - **Reproducible artifacts:** `apps/web/scripts/build-libghostty-wasm.sh` builds the two WASM artifacts from the pin in `native/libghostty-vt/VERSION`; the WASM embeds the revision and an ABI test checks it against mobile's `VERSION`. Both web and native artifacts must be rebuilt when the pin changes.
  - Client output buffer capped at 512 KiB (`terminalOutput.ts`), separate from the server's history cap.
- **Surfaces:** web and desktop (WASM); Android shares the C ABI (`libghostty-vt` + Canvas view via JNI); iOS uses an xcframework from a VVTerm fork (per the mobile inventory), so "shared with mobile" is exact for Android and partial for iOS.
- **Where the code lives:** `apps/web/src/terminal/ghostty/surface.ts` (2024 lines), `core.ts` (1242), `renderer.ts` (272), `runtime.ts` (233), `keyCodes.ts` (267), `README.md`, `vendor/`, `fonts/`; tests alongside (`surface.test.ts` 1062, `runtimeAbi.test.ts` 717); `apps/web/scripts/build-libghostty-wasm.sh`; `native/libghostty-vt/`; `docs/internals/terminal-runtime.md`.

## Problems today

- `surface.ts` is 2024 lines combining input, IME, selection, scrolling, sizing, links and blinking.
- The theme is read from computed CSS variables, so a theme change needs a re-read and re-render rather than a token subscription.
- Cursor blinking is a continuous repaint while a terminal is focused (allowed by the instant-list rule for terminal output, but it must stop when the window is hidden or unfocused; not verified).

## Remodel goals

- **Experience:** terminal colours come from the token pipeline's terminal roles for every theme, and the canvas matches the panel's plane exactly (no seams).
- **Motion:** none. The terminal canvas is never animated (design direction §8, §3.10); transitions happen on the container.
- **Performance:** keep: `libghostty-vt` WASM, Canvas 2D renderer, singleton runtime, replay protection, reproducible build and ABI check. Rebuild around it: a typed adapter between the v2 terminal component and the surface (mount, resize, theme, focus, dispose) so React never touches frames; split `surface.ts` by concern if it helps maintenance, without changing behaviour. Budgets: no frames while hidden or unfocused beyond cursor blink policy; 1 MB/s output bursts render without long tasks over 50 ms. Architecture §1.3 says "Keep" for the terminal engine; do not port to another renderer or WebGL without measurements.

## Done when

- [ ] The engine runs unchanged in behaviour inside the v2 terminal, with the existing test suites green.
- [ ] Theme changes apply through tokens without reading computed styles per frame.
- [ ] Hidden and unfocused terminals do not render (harness check), and blinking stops when the window loses focus.
- [ ] The ABI pin check and reproducible build stay in CI.
