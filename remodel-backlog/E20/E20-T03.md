# E20-T03 · Terminal selection, links and chat context

## What it is

Three ways terminal output connects to the rest of the app. **Selection to chat:** selecting lines shows a small popup with "Add to chat" (and Copy), which turns the excerpt into a terminal-context chip in the composer with its label and line range, so the agent sees the exact output. **Links:** URLs and file paths (including `path:line:col`) are detected, even across wrapped lines; activating a path opens it in the File surface or the preferred editor, and a URL opens according to the "Open links in" preference (in-app browser or system browser). **Context menu:** Add to chat, Copy, Paste.

## When it is used

- A test fails in the terminal: select the failure and "Add to chat" so the agent can fix it.
- A compiler prints `src/app.ts:42:7`: open the file at that line.
- A dev server prints `http://localhost:5173`: open it in the in-app browser beside the thread (desktop) or the system browser.

## How it works today

- **Entry points:** mouse selection in the terminal (popup), right-click (context menu: Add to chat, Copy, Paste), modifier-click on a link (Cmd-click on macOS, Ctrl-click elsewhere, `isTerminalLinkActivation`).
- **Behaviour to preserve:**
  - The selection popup appears after a selection settles; request ids prevent a late popup from an older selection.
  - "Add to chat" creates a terminal-context chip (`lib/terminalContext.ts`) with the terminal label and line range; chips show in the composer (`ComposerPendingTerminalContexts`, `TerminalContextInlineChip`) and expand on hover (E14-T04).
  - Link detection: URLs first, then file paths that do not overlap a URL, across wrapped lines (`collectWrappedTerminalLinkLine`); relative paths resolve against the terminal's cwd (`resolvePathLinkTarget`).
  - Path links open the file in the panel or the preferred editor (`openTerminalPath`, `editorPreferences.ts`); failures are written into the terminal ("Unable to open path").
  - URL links go through `openTerminalLinkInPreview` and the link preference (E21-T09); holding the modifier forces the system browser; without a local API the terminal prints "Opening links is unavailable in this browser."; errors show a toast "Unable to open link". Whether a plain click (without the modifier) ever opens a link is not verified.
  - Copy/Paste through the clipboard; paste into the PTY.
- **Surfaces:** web and desktop. Mobile has a `TerminalContextSheet` for adding terminal output to chat (E33-T04).
- **Where the code lives:** `apps/web/src/components/ThreadTerminalDrawer.tsx` (popup ~251-292, link handling ~785-830), `terminal-links.ts`, `lib/terminalContext.ts`, `lib/selectionActions.ts`, `components/preview/openTerminalLinkInPreview.ts`, `components/chat/TerminalContextInlineChip.tsx`, `components/chat/ComposerPendingTerminalContexts.tsx`, `composerDraftStore.ts`.

## Problems today

- Popup timing relies on request ids to avoid races.
- The context menu depends on `localApi`; link activation needs a modifier that is not discoverable.

## Remodel goals

- **Experience:** "Add to chat" is one shared selection action across the terminal, files and diffs (same chip family), with a keyboard path (select with Shift+arrows in the terminal's selection mode, then a key). Hovering a link shows the modifier hint.
- **Motion:** the popup uses `pop` from the selection; adding to chat can match-cut a chip into the composer when the composer is visible, else instant; the terminal canvas does not move.
