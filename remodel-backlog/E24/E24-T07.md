# E24-T07 · PR editing: title, labels, reviewers, reactions

## What it is

Changing a PR's metadata from E6: rewrite the **title** and **description** (markdown editor with Write and Preview), edit your own comments, add or remove **labels**, request or withdraw **reviewers**, and add **emoji reactions** to the PR and its comments.

## When it is used

Tidying the title and description an agent generated, asking a teammate for review, labelling for release notes, acknowledging a comment.

## Current screen

No screenshot: the pickers live in the PR detail Summary tab, which could not be reached in the capture environment (see `shots/gitpr/gaps.md`).

In words: the title edits inline from the header; the Description section has an edit button that swaps to a Write/Preview editor. Reviewers and Labels meta rows open searchable popovers with "Applied" and "Already asked" groups. Comment cards carry a reaction bar with "Add a reaction".

## How it works today

- **Entry points:** title edit button; Description edit; Reviewers and Labels rows in Summary; reaction bar on comments and the PR body.
- **Behaviour to preserve:**
  - Edits are optimistic and roll back on failure with a host-specific error hint.
  - Label candidates and reviewer candidates load on demand (`pullRequestsLabelCandidates`, `pullRequestsReviewerCandidates`); already applied or asked are grouped.
  - Where the host cannot list reviewers, the page takes a typed name instead of offering a guessed list.
  - Markdown preview uses the same renderer as the Summary.
- **Per host:**
  - Title and description: all five hosts.
  - Editing own comments: GitHub, GitLab, Bitbucket, Forgejo/Gitea; not Azure DevOps.
  - Labels: GitHub and Forgejo/Gitea only (needs triage/write permission); not GitLab, Bitbucket or Azure DevOps today.
  - Reviewers: request on all five; candidate list on all except Azure DevOps (type a name).
  - Reactions: GitHub, GitLab, Forgejo/Gitea; not Bitbucket or Azure DevOps.
- **Surfaces:** web and desktop. Server RPCs `pullRequestsUpdate`, `pullRequestsUpdateComment`, `pullRequestsSetLabels`, `pullRequestsRequestReviewers`, `pullRequestsSetReaction`.
- **Where the code lives:** `apps/web/src/components/pullRequest/PullRequestEditButton.tsx`, `pullRequestEditing.logic.ts`, `PullRequestMarkdownEditor.tsx`, `pullRequestMarkdown.logic.ts`, `PullRequestLabelPicker.tsx`, `PullRequestReviewerPicker.tsx`, `PullRequestReactions.tsx`, `pullRequestReactions.logic.ts`.

## Problems today

- GitLab supports labels on merge requests but E6 does not offer them (capability not declared); a gap rather than a host limit.
- Three popover pickers with slightly different patterns.

## Remodel goals

- **Experience:** one searchable picker pattern for labels, reviewers and assignees; label colours from the host shown as a swatch beside the name, never as the only cue.
- **Motion:** popovers `pop` from the trigger; applied chips appear with `reveal`; a reaction count uses `numberChange`.

## Done when

- [ ] All edits optimistic with rollback, per-host gating as listed, typed-name fallback for Azure reviewers.
- [ ] One picker component for labels and reviewers.
- [ ] Decision recorded on adding GitLab labels.
- [ ] Dark and light, keyboard reachable, reduced motion handled.
