# E24-T10 · Agent handoffs from a PR

## What it is

**Agent handoffs** turn a PR problem into agent work in one click. From a PR, E6 prepares a thread (checking the PR out into a new worktree by default, or into the local checkout), opens a draft and writes a prompt with the relevant context as chips: review findings to fix, failing checks to fix, conflicts to resolve, a question to ask, or selected diff lines to address. The **Start thread from pull request** dialog does the same from a typed PR reference.

## When it is used

- A reviewer left five comments: "Fix findings".
- CI failed: "Fix" on the failing check.
- The PR conflicts with main: "Resolve conflicts".
- Picking up someone's PR locally: "Check out", or type `#42` in the branch picker → "Checkout pull request".

## How it works today

- **Entry points:** Check out, Resolve conflicts, per-finding Fix, Fix findings, checks Fix (E24-T08), Ask, Code tab "Add to agent"; branch picker "Checkout pull request" → dialog (E23-T03); `usePreparePullRequestThreadAction` (`gitPreparePullRequestThread`), `gitResolvePullRequest`.
- **Behaviour to preserve:**
  - Default checkout target is a worktree; local is offered.
  - Prompts per kind (`handoffPrompt`): for example "Fix the failing check quoted below. Reproduce it locally first — the name is all the host reported…"; findings are summarised (`summarizePullRequestFindings`) and attached as review-comment chips.
  - The latest handoff replaces earlier handoff text and chips in the draft but keeps text the user typed (`lastHandoffPromptByDraft`, module-level state).
  - Dialog resolution is debounced 450 ms and cached (`readCachedPullRequestResolution`); states resolving, resolved, error, preparing local or worktree.
  - The created thread is linked to the PR (E24-T11).
- **Per host:** checkout is implemented for all five (`checkoutChangeRequest`); findings exist only where the host has review threads (not Azure DevOps); checks Fix needs reported checks.
- **Surfaces:** web and desktop. Server: `GitManager` prepares PR threads (E23-T04).
- **Where the code lives:** `apps/web/src/components/pullRequest/PullRequestDetailPanel.tsx:1157–1400`, `pullRequestDetail.logic.ts` (`handoffPrompt`, `pullRequestHandoffLabels`, `summarizePullRequestFindings`), `components/PullRequestThreadDialog.tsx` (`:39`), `state/sourceControlActions.ts:311,373`, `pullRequestReference.ts`, `composerDraftStore.ts`, `reviewCommentContext.ts` (477), `hooks/useHandleNewThread.ts`.

## Problems today

- Coupled to composer internals: writes directly into the legacy draft store, with module-level state for the last prompt.

## Remodel goals

- **Experience:** handoffs are the PR panel's key light when something is broken: one obvious "Fix with agent" with a preview of the prompt and the target (this thread / new worktree thread).
- **Motion:** match cut from the finding or check row into the composer chip (design direction 3.3/3.8 continuity), then the panel stays put.
