# E24-T11 · PR to thread linking

## What it is

**PR-to-thread links** record which pull requests belong to which threads, many-to-many: a thread can have several PRs (including PRs in other repositories on the same host), and a PR can be linked to several threads. Links come from the user (Link / Unlink), from agents (the `link_pull_request` tool), from a stacked action that created the PR, and from the server's automatic discovery of the PR for a thread's branch. Linked PRs show on the thread (PR chip, sidebar badge, **Linked pull requests** panel) and on PR rows (linked-thread chips).

## When it is used

Knowing which PR an agent's thread produced, jumping between a PR and the conversation that wrote it, and letting a merged PR settle its thread automatically.

## How it works today

- **Entry points:** command palette "Link pull request"; Linked pull requests panel "+ Link" and row menu "Unlink from thread"; right-click a PR link → "Link pull request to thread" / "Unlink from this thread"; "Link this PR" from the branch badge; "Link to thread" from the PR page (thread links picker with thread and project search, `PullRequestThreadLinks.tsx`); sidebar thread PR badge and branch-toolbar PR chip open the panel; agents call `link_pull_request` (MCP).
- **Behaviour to preserve:**
  - Link dialog accepts a URL or `#42`, shows a preview (`PullRequestLinkPreview`) and a candidate picker.
  - Panel states: empty ("No linked pull requests" with Link), waiting for host state, multiple PRs, stacks shown as chains; refresh behaviour and "synced N ago".
  - A link is identified by host, repository and number and can cross projects within an environment. The **current pull request** is the one single-PR controls and older clients use; open work takes precedence.
  - **PR sync**: a reactor refreshes each linked PR once per cadence and discovers stack layers (`PullRequestSyncReactor`, `ThreadPullRequestReactor`; they also discover a thread's PR by branch at startup, with limited lookups for settled threads). Merged PRs can **auto-settle** their threads (E09-T03).
  - Capability negotiation: environment capabilities `threadPullRequests` (multiple links) and `threadPullRequestLinking`; older servers support one PR per thread (`threadPullRequestLinkMode`); neither flag hides linking actions.
  - Linking a created PR never fails a stacked action.
- **Surfaces:** web and desktop (all entry points). **Mobile:** shows linked PR chains read-only in the git overview sheet and opens them on the host; no Link or Unlink action was found in `apps/mobile/src` (a one-way door to fix). Server: link commands in the decider (`thread.pull-request.sync`, `pull-request-link.sync`), projection `ProjectionThreadPullRequests`, `linkedThreads.ts`, `pullRequestsLinkedThreads`.
- **Where the code lives:** `apps/web/src/components/pullRequest/LinkPullRequestDialog.tsx` (`:119`, host `:52`), `PullRequestLinkPreview.tsx`, `PullRequestCandidatePicker.tsx`, `ThreadPullRequestsPanel.tsx` (`:223`), `PullRequestThreadLinks.tsx` (`:33`), `PullRequestContextDetails.tsx`, `hooks/usePullRequestLinking.ts`, `hooks/useSupportsMultiplePullRequests.ts`, `state/pullRequests.ts` (`linkedPullRequestDetailAtom`), `components/ThreadStatusIndicators.tsx:194`; server `orchestration/Layers/PullRequestSyncReactor.ts` (341), `ThreadPullRequestReactor.ts` (370), `pullRequest/linkedThreads.ts`, `git/linkCreatedPullRequest.ts`; mobile `features/threads/git/GitOverviewSheet.tsx`.

## Problems today

- Many entry points with slightly different wording ("Link pull request to thread", "Link to thread", "Link this PR").
- Mobile cannot link or unlink.
- Automatic discovery is invisible: users cannot tell a manual link from a discovered one.

## Remodel goals

- **Experience:** one link model with the same wording everywhere, a visible source ("linked by you", "found from branch", "created here"), and the way in and the way out on every client (M4 exit criterion).
- **Motion:** a new link's chip appears with `reveal`; nothing animates on sync.
- **Performance:** sync stays server-side; clients receive link deltas only (thread payload gate in CI, see E36-T05).

## Done when

- [ ] Link and unlink from every entry point listed, on web, desktop and mobile.
- [ ] Multi-link and single-link (older server) modes both work; capability flags respected.
- [ ] Link source shown; auto-settle on merge unaffected.
- [ ] Thread payload size within the CI "Thread transfer impact" ceilings.
- [ ] Dark and light, keyboard reachable, reduced motion handled.
