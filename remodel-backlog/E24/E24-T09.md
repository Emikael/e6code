# E24-T09 · Stacked pull requests

## What it is

A **stack** is a chain of PRs where each one builds on the branch of the one below. E6 detects stacks, shows them as layers with a stack badge, and acts on them: **Merge stack** merges the selected PR together with the unmerged layers below it, and **Rebase stack** updates the remote branches bottom to top. Rebase rewrites history and can restart checks, so it asks first.

## When it is used

Agents and people who split large changes into small reviewable PRs; landing a whole chain at once.

## Current screen

No screenshot: no stacked PRs existed in the capture environment (see `shots/gitpr/gaps.md`).

In words: a stack glyph on rows and in the detail header opens a popover listing the layers (each a PR with its state); a stack menu offers merge and update actions with a confirmation dialog. States include "Retry stack refresh", notice text, and whether the stack shown is a saved snapshot or live.

## How it works today

- **Entry points:** stack glyph on a row, stack chip in the detail header, stack menu; Linked pull requests panel lists stacks.
- **Behaviour to preserve:**
  - Saved snapshot fallback paints the stack before the live one loads (`pullRequestStackSnapshot.ts`).
  - Merge stack: selected PR plus unmerged layers below, with a merge-strategy confirmation.
  - Rebase stack: bottom to top on the remote; confirmation warns about history rewrite and restarted checks; viewer permission `stackRebase` governs it.
  - PR sync discovers stack layers for linked threads (E24-T11).
- **Per host:** GitHub only (`stacks` and `stackActions` capabilities; GitHub's own stacked-PR objects via `githubStackActions.ts`). On GitLab, Bitbucket, Azure DevOps and Forgejo/Gitea there are no host stacks; chains are only inferred from base branches and no stack actions are offered.
- **Surfaces:** web and desktop; mobile shows linked PR chains read-only in the git overview sheet. Server: `pullRequestsStack`.
- **Where the code lives:** `apps/web/src/components/pullRequest/PullRequestStackPopover.tsx`, `PullRequestStackMenu.tsx` (`:30`), `PullRequestStackLayers.tsx`, `PullRequestStackLayerContent.tsx`, `PullRequestStackHeader.tsx`, `pullRequestStackSnapshot.ts`, `state/usePullRequestStack.ts`; server `pullRequest/githubStackActions.ts`.

## Problems today

- Users on other hosts get inferred chains with no explanation of why actions are missing.
- Snapshot vs live is a subtle text notice.

## Remodel goals

- **Experience:** a vertical stack diagram (bottom = base) with each layer's state in words and a clear "what Merge stack will do" preview listing exactly which PRs merge.
- **Motion:** layers reveal with the 24 ms stagger capped at 8; a merged layer swaps its mark with `checkDraw`.
