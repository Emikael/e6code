# E14-T08 · Prompt history recall and length validation

## What it is

Two small composer behaviours. **Prompt history recall**: on an empty composer, ArrowUp walks back through the prompts already sent in this thread and ArrowDown walks forward, like a terminal; going past the newest entry restores the unsent draft. **Prompt length validation**: a message cannot exceed 120,000 characters; an over-limit prompt stays in the composer with a message saying how far over it is, instead of being dropped or truncated.

## When it is used

- Re-sending or tweaking the previous instruction ("run the tests again").
- Pasting a very long document into the prompt by mistake and needing to know why Send did nothing.

## Current screen

No screenshot: the over-limit message and recall were not captured. The validation message appears just above the composer as one line of error text: "Prompt is N characters over the 120,000-character limit. Shorten or split it before sending."

## How it works today

- **Entry points:** ArrowUp / ArrowDown in an empty composer (key handler `onComposerCommandKey` in `ChatComposer.tsx`); Send (validation runs in `submitComposerDraft`).
- **Behaviour to preserve:**
  - History is per thread and text only. It is derived from the thread's user messages on each keypress, so nothing is stored or synced. Attachment-only messages (sent with a bootstrap placeholder prompt) are handled; review-comment blocks appended at send time and terminal-context blocks with their `@terminal-…` labels are stripped from recalled text, while anything the user typed is kept byte for byte.
  - The recall position is anchored by message ID, so an optimistic message being replaced by the server's, or an older page loading, does not move it; consecutive duplicate prompts collapse. Once the user edits the recalled text, browsing ends.
  - ArrowDown past the newest entry restores the draft that was there before recall started.
  - Length counts the larger of the trimmed prompt and the prompt with assistant citations expanded for the provider (`expandAssistantCitationsForProvider`), against `PROVIDER_SEND_TURN_MAX_INPUT_CHARS` (120,000). Validation applies to provider turns, not to question answers. The server enforces the same limit (`Normalizer.ts`).
  - The draft is never cleared when validation fails.
- **Surfaces:** web and desktop. Mobile: not verified whether recall exists; the limit is enforced by the shared contract.
- **Where the code lives:** `apps/web/src/components/chat/composerPromptHistory.ts` (216), `chat/composerSubmission.ts` (50), `ComposerPromptLengthValidation.tsx`, `packages/contracts/src/orchestration.ts:182`.

## Problems today

- Validation appears only on Send; nothing warns while typing toward the limit.
- Recall is invisible: there is no hint that ArrowUp works.

## Remodel goals

- **Experience:** an over-limit prompt shows a live counter near the send button once it passes a threshold (for example 90%), and Send is disabled with the reason as its tooltip. A first-use hint teaches ArrowUp recall in the composer placeholder or shortcut list.
- **Motion:** rejected input is the one place the `shake` preset is allowed (§3.9); recall swaps text instantly (typing surfaces are instant).

## Done when

- [ ] Over-limit prompts stay in the composer, with the exact excess shown; counting includes expanded citations.
- [ ] Unit tests for history stepping and length counting kept or ported.
- [ ] Dark and light reviewed; messages announced to screen readers.
