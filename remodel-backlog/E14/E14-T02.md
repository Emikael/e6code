# E14-T02 · Composer: mentions, slash commands and skills

## What it is

Typing a trigger character in the composer opens a command menu: `@` searches workspace files and folders to mention, `/` lists commands, `$` lists skills (reusable agent instructions the provider knows about), and `#` lists pull requests in the project's repository. Picking an item inserts an inline chip. Commands are either E6 Code's own (`/model`, `/plan`, `/default`, `/usage-limits`) or the provider's native slash commands (such as `/compact`, `/feedback`, `/logout`), and the skill catalogue comes from the server per provider.

## When it is used

- Pointing the agent at specific files ("fix the bug in @src/App.tsx").
- Running a provider command (`/compact` to shrink context, `/feedback` on Codex) or switching mode (`/plan`).
- Invoking a skill the user has installed for Claude, Codex, Cursor, Grok, OpenCode or Antigravity.
- Referring to a pull request (`#142`) so the agent gets its context.

## How it works today

- **Entry points:** typing `@`, `/`, `$` or `#` at a trigger position (`detectComposerTrigger` in `composer-logic.ts`); arrow keys and Enter/Tab to pick, Escape to dismiss the trigger (dismissal is remembered for that trigger so the menu does not reopen while typing on); mouse click. `/model` also opens the model picker (E15-T01).
- **Behaviour to preserve:**
  - `@`: workspace path search on the environment server (files and folders, language icons), with loading, results and "none" states. Electron folder drops also become path mentions (E14-T03).
  - `/`: E6 commands `/model`, `/plan` and `/default` (the last two only when plan mode is enabled and the provider supports it), `/usage-limits` (E15-T04), then provider slash commands from `ServerProvider.slashCommands` (`/compact` only where the provider lists it). Skills also appear in `/` as `/skill:name` when Settings → General → "Show skills in slash menu" (`showSkillsInSlashMenu`) is on.
  - E6 commands and skill mentions work mid-line; provider commands must start the message (user docs).
  - `$`: skills from `ServerProvider.skills`, per provider: Claude merges user, project, plugin and bundled skills with SDK init commands (`userInvocationOnly`; skills marked `disable-model-invocation` are limited to one per message); Codex from the app server; Cursor, Grok and Antigravity from disk (Antigravity: `.agents/skills`, `.gemini/skills`, `.agent/skills` in the project, two user directories); OpenCode from its server. OpenCode's list is cached about 30 s; "Refresh provider status" reloads.
  - `#`: recent pull requests for the project repository, digits filter to an exact number lookup, text search; inserts a PR chip. Empty state when the project has no supported host or the user has no access.
  - Ranking and highlight: `composerSlashCommandSearch.ts`, `providerSkillSearch.ts`, `composerMenuHighlight.ts`.
  - Inserted mentions are atoms; chips are draggable inside the prompt.
- **Surfaces:** web and desktop. Mobile has its own popover (`use-composer-command-menu.ts`, 568 lines; `ComposerCommandPopover.tsx`) owned by E32-T04, sharing ranking in `@e6tools/shared` and `@e6tools/client-runtime/providerSkills`. Server: skill discovery `apps/server/src/provider/Drivers/ClaudeSkills.ts`, `CursorSkills.ts`, `GrokSkills.ts`, `AntigravitySkills.ts`, `ClaudeSkillDispatch.ts`; Codex skills from app-server; published on `ServerProvider.skills` / `slashCommands`.
- **Where the code lives:** `apps/web/src/components/chat/ComposerCommandMenu.tsx` (244), `useComposerTriggerState.ts`, `composerSlashCommandSearch.ts`, `composer-logic.ts:221`, `providerSkillSearch.ts`, `lib/composerPathSearchState.ts`, `composerMenuHighlight.ts`; menu items assembled inline in `ChatComposer.tsx` around lines 2280–2450.

## Problems today

- Menu items are built inside a large `useMemo` in `ChatComposer.tsx`, mixing E6 commands, provider commands and skills in one place.
- Several items are gated by driver-kind checks in the client rather than by provider capabilities (E37-T11 counts about 60 such checks across clients).
- The `#` menu has only an empty state in environments without GitHub access; the reason is not differentiated (no host, no auth, no repo).

## Remodel goals

- **Experience:** one menu primitive shared with the command palette's list (floating plane, `pop` preset from the caret), with sentence-case group labels (E6 commands, Provider commands, Skills), a right-aligned mono column for the trigger text, and a clear reason in the empty state.
- **Motion:** results are instant while typing (no row stagger); the highlight follows the keyboard with a ≤ 90 ms tween, instantly on key repeat (design direction §3.7, §3.10).
- **Performance:** path search is debounced and cancels stale requests; the menu never blocks typing (input-latency budget applies).

## Done when

- [ ] All four triggers work with keyboard and pointer, including mid-line rules for E6 commands and start-of-message rule for provider commands.
- [ ] Which commands and skills appear is read from the provider snapshot and capability descriptor (E37-T11), not driver kind, with a per-provider row in the parity checklist (Codex, Claude, Cursor, Grok, OpenCode, Antigravity).
- [ ] Empty, loading, error and no-access states designed in dark and light, including the `#` reasons.
