# E14-T04 · Context chips

## What it is

Context chips are compact tokens in the composer that stand for a piece of context the agent should see: a terminal excerpt, a diff review comment, a browser preview annotation, a picked page element, a file, a pull request, or a quote from an earlier assistant reply (citation). Each chip is backed by a typed **context record** (keyed by `contextId`, never holding file bytes) and appears in the prompt text as a **context reference** link (`e6-context://v1/<kind>/<id>`). Hovering a chip shows its details; selecting it opens the source. The same chips render inside sent messages.

## When it is used

- Selecting lines in the terminal and sending them to the agent ("why does this fail?").
- Turning review comments written on a diff into one instruction.
- Annotating a page in the in-app browser or picking an element and asking for a change.
- Citing a sentence from the agent's earlier answer.
- Copying a prompt with chips from one thread and pasting it into another.

## How it works today

- **Entry points:** terminal selection popup "Add to chat" (E20), diff review comments "send to composer" (E18-T04), browser annotation and element picker (E21-T05), assistant selection toolbar "Cite" (E13-T15), PR `#` mention (E14-T02), paste of copied chips, file chips from `@` mentions.
- **Behaviour to preserve:**
  - A registry (`contextPresentationRegistry.ts`) renders each record kind as a chip with a popover, in the composer and in sent user messages, from one presentation (`composerContextPresentation.tsx`, `contextChipParts.tsx`).
  - Records are size-capped in contracts (`composerContext.ts`): terminal text 64,000 chars, review text 16,000, review diff 32,000, element HTML and styles 8,000 each, preview comment 8,000, labels 200, whole serialised context 16,000,000.
  - Terminal excerpts expire with the terminal session; expired ones are dropped on send with a toast. Terminal chips are sent as `@terminal-1:12-13` labels plus a trailing block.
  - Removing a chip can be undone (`composerContextUndo.ts`).
  - Copy and paste: chips carry over between drafts and are re-fetched from the source environment; "Copy message as Markdown" replaces chips with links (`data-markdown-copy`).
  - Records and references are persisted with the draft (E14-T06) and with stash entries (E14-T07); older drafts that used producer IDs are migrated on load.
  - Citations store selectors (text, offsets, prefix, suffix) so selecting the chip scrolls back to the quoted source.
- **Surfaces:** web and desktop. Mobile has `ComposerContextSheet` and a context clipboard (E32-T03). Wire contract: `ComposerContextRecord`, `AssistantCitation` in `packages/contracts`.
- **Where the code lives:** `apps/web/src/composerContextPresentation.tsx`, `contextChipParts.tsx`, `contextPresentationRegistry.ts`, `lib/composerContextRecords.ts`, `lib/composerContextReferences.ts`, `chat/composerContextUndo.ts`, `chat/TerminalContextInlineChip.tsx`, `ComposerPendingTerminalContexts.tsx`, `reviewCommentContext.ts`, `packages/contracts/src/composerContext.ts`.

## Problems today

- Chip renderers for sent messages are duplicated in `MessagesTimeline.tsx` versus the composer (report 02, S-5).
- Six record kinds each have their own producer, storage field and migration in the draft store.

## Remodel goals

- **Experience:** chips are one primitive (`--radius-sm`, icon plus short label, mono only for paths and line ranges), identical in composer and timeline; hover cards use the floating plane; every chip says what it is in words, not colour.
- **Motion:** inserting a chip from another surface (terminal, diff, browser) is a user-caused move between places, so it is a match cut from the source selection into the composer or a cut (§5.3 rule 3); removal with undo uses `swap`.
- **Performance:** records never carry bytes; render chips from records without re-parsing the whole prompt on each keystroke.

## Done when

- [ ] Every record kind renders through one registry in composer and timeline (shared with E13-T07).
- [ ] Contract size caps enforced with a readable message; expired terminal excerpts are dropped with a notice on send.
- [ ] Copy/paste between threads and environments and "Copy message as Markdown" keep working.
- [ ] Legacy persisted references (producer-ID links, terminal placeholders) still resolve after the rewrite.
