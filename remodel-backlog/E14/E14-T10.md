# E14-T10 · Type-to-focus and global composer focus

## What it is

In a thread, the user can start typing without clicking the composer: any printable key pressed while nothing editable or interactive has focus is redirected into the composer. Plain-text paste works the same way. The composer also regains focus when the window comes back into focus and when the command palette closes.

## When it is used

- After clicking in the timeline, reading, and then typing a follow-up straight away.
- After returning to the app window from another app.
- After running a command from the palette.

## Current screen

No screenshot: the behaviour has no UI of its own.

## How it works today

- **Entry points:** document-level keydown and paste listeners in `ChatView.tsx`; window focus; palette close (`keyboard-focus.md`: "command palette returns focus to composer"); PageUp/PageDown from the composer scroll the timeline (owned by E13-T05).
- **Behaviour to preserve:**
  - A key redirects only if it is a single printable character, no Cmd, Ctrl or Alt is held, IME composition is not active, and the event was not already handled.
  - Not redirected when the event path is inside an editable element (`input`, `textarea`, `select`, `contenteditable`, `role="textbox"`), an interactive element (buttons, links, `summary`, roles button, checkbox, menuitem, option, radio, switch, tab, treeitem; tree rows keep type-ahead for sidebar navigation), or while any floating layer is open (modal dialogs, alert dialogs, command dialog, sheets, the mobile sidebar sheet, menus, selects, popovers, comboboxes, autocompletes).
  - The terminal and in-app browser keep their keys (they are editable or focused surfaces).
  - The right-panel surface launcher claims its shortcut letters while visible (`data-surface-launcher-keys`); those letters open surfaces instead.
  - Paste-to-focus only for plain text with no files (files go to the composer's own paste handler).
- **Surfaces:** web and desktop. Mobile: not applicable (hardware keyboard commands are E35/E32).
- **Where the code lives:** `apps/web/src/components/ChatView.tsx:683-795` (selectors, `shouldRedirectInputToComposer`, `shouldTypeToFocusComposer`, `pasteTextToFocusComposer`), `ChatView.logic.ts:1345`, `lib/editableFocus.ts`.

## Problems today

- Focus rules are three hard-coded selector lists inside ChatView; every new floating layer or panel must remember to match them.
- The palette's "return focus" and the workspace-area navigation (E08-T04) are separate mechanisms.

## Remodel goals

- **Experience:** one focus policy module in `next/` that v2 primitives register with (a floating layer declares itself once), shared with workspace focus areas (F6) and the command palette.
- **Performance:** a single passive listener; no DOM queries per keystroke beyond the event path check.

## Done when

- [ ] Every rule above has a test (printable keys, modifiers, IME, editable, interactive, floating layers, launcher keys, paste with and without files).
- [ ] v2 floating primitives (menu, popover, dialog, sheet) are excluded automatically, not by selector lists.
- [ ] Terminal, browser panel and diff comment editors never lose keys to the composer.
- [ ] Focus returns to the composer after the palette closes and on window focus.
