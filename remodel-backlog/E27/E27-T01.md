# E27-T01 · Provider instances

## What it is

Settings → Providers is where a user connects E6 Code to the coding agents installed on an environment and configures how each one runs. Each **driver** (Codex, Claude, Cursor, Grok, OpenCode, Antigravity) has a default **instance**; the user can add more instances of the same driver, each with its own label, accent colour, binary path, home or config directory and environment variables. This is how one machine runs a personal and a work Claude account side by side, or routes Claude through OpenRouter. The page also shows each instance's health (installed, signed in, version, update available) and lets the user enable or disable it.

## When it is used

- First run: the welcome wizard's "Check your agents" step and a new user with no signed-in provider land here.
- A provider shows "Not found" because its CLI is not on the server's PATH; the user sets Binary path (for example a version-manager path, or `cursor-agent` for Cursor).
- A user adds a second Claude account (`CLAUDE_CONFIG_DIR=~/.claude_personal`) or a second Codex account sharing sessions through a shadow home.
- A user sets environment variables for a router (`ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`) or launch arguments.
- The sidebar nav shows "N signed out" on Providers, and the user comes to fix it.

## How it works today

- **Entry points:** settings nav "Providers" (badge "N signed out"); deep link `/settings/providers?instanceId=&environmentId=`; settings search; welcome wizard step; provider status banners in a thread link here (E13-T16); "+" opens the Add provider instance wizard.
- **Page layout:** an environment selector strip ("device tabs"; the page edits one environment at a time, not the whole scope), a refresh button with "Checked …" text (E27-T05), "+" to add an instance. A two-pane list/editor: the left list shows each instance's icon, name, id chip, version, update-available icon, status dot plus words ("Not found", "Authenticated · Claude Api Subscription", "Disabled"), enable switch. The right editor has sections Display name (with accent colour picker and status text), Setup (Antigravity only, E27-T04), Runtime (per-driver fields), Environment (name/value rows), Models (E27-T03). Below: Usage providers (CLIProxyAPI hubs, owned by E28-T04) and Advanced (health check interval, E27-T05). A "Limited permissions" row appears for read-only sessions.
- **Per-driver runtime fields** (schema-driven from `packages/contracts/src/settings.ts`):

| Driver (id)                     | Fields                                                                                                            |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Codex (`codex`)                 | Binary path, CODEX_HOME path, Shadow home path, Launch arguments                                                  |
| Claude (`claudeAgent`)          | Binary path, CLAUDE_CONFIG_DIR path, Launch arguments, Auto-compact after (100,000 to 1,000,000; empty = default) |
| Cursor (`cursor`, Early Access) | Binary path (`cursor-agent`), API endpoint                                                                        |
| Grok (`grok`, Early Access)     | Binary path                                                                                                       |
| OpenCode (`opencode`)           | Binary path, Server URL (empty = E6 starts OpenCode locally), Server password                                     |
| Antigravity (`antigravity`)     | Sign-in method, API key, GCP project, GCP location, Binary path (E27-T04)                                         |

- **Add provider instance wizard:** three steps in the current UI (Driver, Identity, Config; report 05 describes two). Identity holds Label, Instance ID (auto-slugged from the label, required, validated unique) and Accent colour; Config holds the driver's fields.
- **Storage:** instance config is server-side (`providerInstances`, plus legacy `providers`) in the environment's `settings.json`; sensitive values (tokens, passwords, keys) are write-only and come back redacted (`SECRET_VALUE_REDACTED`).
- **Behaviour to preserve:**
  - Multiple instances per driver, each with its own binary, home dir, env vars and accent; the default instance cannot be deleted, extra ones can.
  - Codex accounts can share sessions via `CODEX_HOME` + Shadow home path; a fully separate home cannot continue another home's threads (and the model picker offers switching only between instances sharing a `CODEX_HOME`, E15-T01).
  - Unknown drivers (from a newer server or a fork) keep their config untouched and render a generic card.
  - Disabling an instance keeps its config; a text-generation model selection that points at a deleted instance is reset.
  - Read-only sessions see the page without edit controls ("Limited permissions").
  - Environment unavailable: placeholder for that environment's tab.
  - Status always pairs a dot with words.
  - Not available on mobile (mobile has no provider settings page; Antigravity sign-in is explicitly web/desktop only).
- **Surfaces:** web and desktop (same page), server (config, probes). Mobile: none.
- **Where the code lives:** `apps/web/src/components/settings/ProviderSettingsPanel.tsx` (1,177 lines; `EnvironmentProviderSettings` at about line 552), `ProviderInstanceCard.tsx` (917), `ProviderSettingsForm.tsx` (435, schema-driven fields), `AddProviderInstanceDialog.tsx` (426), `AddProviderInstanceWizardSteps.tsx`, `AddProviderInstanceDialog.logic.ts`, `providerDriverMeta.ts`, `providerStatus.ts`, `providerInstances.ts`; server `apps/server/src/provider/Layers/ProviderRegistry.ts`; contracts `packages/contracts/src/settings.ts`.

## Problems today

- Sign-in state is text only; for five of six providers the user must leave the app to run a CLI login, and the page does not say which command.
- The page is pinned to one environment through its own tab strip, unlike other server pages that use the settings scope breadcrumb.
- The two-pane layout uses a container query (`@min-[48rem]/providers`) with a fixed card height.
- Status messages are long error strings in the list ("Could not start Codex CLI (`codex`). Check Settings → …").
- Driver-specific UI decisions are hard-coded by driver kind instead of read from capabilities (E37-T11).

## Remodel goals

- **Experience:** the list is a status board: each instance shows a status mark (icon + word: Ready, Signed out, Not found, Update available, Disabled) and the one next action ("Run `claude auth login` on vm" with copy, "Set binary path", "Update now"). That next action is the page's only key light. Adding an account is a short sheet with the driver step skipped when opened from a driver's row.
- **Provider marks** render in brand colour here (design direction §6.4); status never by colour alone.
- **Motion:** wizard steps use `sideBySide`; switching the selected instance is a cut; the selection highlight travels with `spring.snappy`.
- **Performance:** status updates for one instance re-render only that row.

## Done when

- [ ] Unknown-driver config round-trips unchanged (test).
