# E27-T05 · Provider status and health refresh

## What it is

E6 Code continuously knows whether each provider on each environment is usable: installed or not, which version, signed in or not (with account type), its models, skills and slash commands, usage limits and update state. The server builds a **status snapshot** per provider instance, refreshes it on a schedule set by the background activity policy, caches the last snapshot on disk so the UI has data instantly at start, and pushes changes to clients. Users can force a refresh with the refresh button on Settings → Providers ("Checked just now").

## When it is used

- App start: the sidebar badge "N signed out", the model picker and thread banners need provider state before anything else.
- After running a CLI login in a terminal, the user presses refresh so E6 Code notices.
- After installing a new model or skill for OpenCode, refresh reloads the lists (OpenCode helpers have a 30-second cache).
- Background: periodic health checks at the interval chosen in Advanced or by the battery profile.

## How it works today

- **Entry points:** Settings → Providers refresh button with relative "Checked …" time; Providers → Advanced health check interval; General → Background activity (profile and per-task overrides, E25-T12); RPC `server.refreshProviders`; `server.getConfig`; `subscribeServerConfig` event `providerStatuses`; mobile "Refresh models" in thread settings.
- **Server** (report 06 F-29): each driver exposes `getSnapshot`, `refresh`, `streamChanges` built with `makeManagedServerProvider`. Snapshot fields: installed, version, auth status (`authenticated` / `unauthenticated` / `unknown` with type and label), message, models, skills, slash commands, usage limits, update state. `ProviderRegistry` (952 lines) aggregates all instances with a 200 ms debounce on change; `providerStatusCache` writes `<baseDir>/caches/<instanceId>.json`; unknown or unavailable drivers get `unavailableProviderSnapshot`. The refresh interval comes from `providerHealthRefreshInterval` and `BackgroundPolicy` (throttled when no client is in the foreground).
- **Behaviour to preserve:**
  - Cached snapshots render immediately at startup and are replaced by live probes.
  - Manual refresh runs on every selected environment (Usage Limits refresh does the same, E28-T02) and updates the "Checked" time.
  - Status is shown with words, not colour alone ("Not found", "Authenticated", "Disabled").
  - Error messages carry the remediation path ("Check Settings → Providers → Codex → Binary path").
  - Disabled instances are not probed (not verified).
  - Snapshot changes for one instance do not resend others (200 ms debounce aggregates).
- **Surfaces:** server; web, desktop and mobile consume it.
- **Where the code lives:** server `apps/server/src/provider/makeManagedServerProvider.ts`, `provider/Layers/ProviderRegistry.ts`, `providerStatusCache.ts`, `providerSnapshot.ts`, `unavailableProviderSnapshot.ts`, `background/BackgroundPolicy.ts`; web `providerStatus.ts`, `ProviderSettingsPanel.tsx`.

## Problems today

- Each `providerStatuses` event carries full snapshots including model and skill lists; size per event is not measured in the inventory.
- The refresh button gives only a relative time; while a probe runs there is no per-instance progress.
- Driver-specific status wording is decided in client code.

## Remodel goals

- **Experience:** one status vocabulary for providers used in settings, the sidebar badge, the model picker and thread banners (E01-T05 status marks). Refresh shows per-instance "Checking…" and returns each row as it lands.
- **Motion:** refresh icon turns once per click (design direction §6.3); rows swap status with `iconSwap`; no continuous spinner.
- **Performance:** status updates for one instance travel and render alone; snapshot payloads stay within the WebSocket budgets (architecture §3.1) and are covered by the thread-transfer CI gate's measurement approach if they grow.

## Done when

- [ ] Cached-at-start, manual refresh, background interval and per-instance push behave as above, with server tests on debounce and cache.
- [ ] The status vocabulary is shared by settings, sidebar badge, picker and banners.
- [ ] Snapshot event size is measured for a heavy environment (many OpenCode models) and recorded against the payload budget.
- [ ] Refresh works for a remote environment and a disconnected one (clear "unreachable" state).
