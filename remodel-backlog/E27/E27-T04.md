# E27-T04 · Antigravity setup and sign-in

## What it is

Antigravity (Google's ACP agent) is the only provider E6 Code installs and signs in to from inside the app. Its Setup section in Settings → Providers downloads and removes a managed runtime on the chosen environment, signs in with Google (open the page or copy the link), handles the case where the browser is on a different device from the environment (paste the `127.0.0.1` return URL), signs out, and lets the user pick another sign-in method: Gemini Enterprise, Gemini API key, or Agent Platform / Vertex AI.

## When it is used

- A user enables Antigravity for the first time: install the runtime, then "Sign in with Google".
- A user runs E6 Code on a remote server and signs in from their laptop's browser; Google redirects to `127.0.0.1` on the laptop, which fails, so the user copies that full address back into E6 Code.
- A company user switches to Gemini Enterprise with a GCP project and location, or a headless server uses an API key ("Connect without a browser").
- A user signs out to change Google accounts, or removes the runtime to free several GB of disk.

## How it works today

- **Entry points:** Settings → Providers → Antigravity → Setup; `/logout` inside an Antigravity thread signs out of Google; RPCs `provider.install.*` (start, cancel, subscribe, remove) and `provider.auth.*` (start, complete, cancel, logout, subscribe).
- **Setup section:** runtime status with Install (progress in MB) and Remove downloaded runtime; Sign in with Google (Open sign-in page / Copy link); a return URL field and Continue for remote sign-in; Sign out; account status ("confirmed access" only after E6 Code verifies it, not when the callback page loads).
- **Runtime fields:** Sign-in method (Google account, Gemini Enterprise, Gemini API key, Agent Platform / Vertex AI), API key, GCP project, GCP location, Binary path (blank = managed runtime, else a compatible executable on PATH).
- **Behaviour to preserve:**
  - Installation continues if the user leaves settings or reconnects; progress resumes on return.
  - Setup requires the `orchestration:operate`-level permission to operate the environment (exact scope not verified); older servers that do not offer setup show an update hint.
  - Remote sign-in: the pasted return URL must be the original `127.0.0.1` address including everything after `?`; only the sign-in attempt that produced it can finish; an expired attempt needs a new sign-in. The return URL contains a temporary code and must only be pasted into this field.
  - Changing sign-in method stops the instance's sessions; the user is told to sign out before replacing an account.
  - The API key is stored in plain text in the environment's settings (docs); ambient `GEMINI_API_KEY` and Google credential variables do not override the selected method.
  - Managed runtime platforms: Apple Silicon macOS, Linux x64/ARM64, Windows x64/ARM64; Intel Macs must use a remote environment; manual install needs the ACP executable and its `localharness_external` helper at the same version.
  - Account actions: Disable, Sign out of Google, Remove downloaded runtime; history and workspace files are kept.
  - Not available on mobile.
- **Surfaces:** web, desktop, server.
- **Where the code lives:** web `components/settings/ProviderSetupSection.tsx` (545 lines), `ProviderSettingsForm.tsx`, `providerDriverMeta.ts`; server Antigravity auth controller and installer (`apps/server/src/provider/Layers/ProviderAuthService.ts`, `providerInstallation.ts`, Antigravity adapter files, see E37-T09); docs `docs/user/providers-antigravity.md`.

## Problems today

- The remote return-URL flow is necessary but unintuitive: users see a browser error page and must know to copy its address.
- The API key is stored in plain text in settings while other provider secrets are redacted on read (docs say plain text; whether it is redacted on read is not verified).
- It is the only provider with in-app auth, so the generic auth UI has been designed around one case.

## Remodel goals

- **Experience:** a stepper that reads top to bottom (Runtime → Sign-in method → Account) with one primary action at a time; for remote environments the app detects that the browser is not on the environment and explains the copy-back step before the user starts, with a paste field that validates the address shape.
- **Motion:** step completion uses `checkDraw`; install progress is a determinate bar tracking real bytes.
- **Security:** treat the return URL and API key as secrets in UI (no echo in logs or toasts).
