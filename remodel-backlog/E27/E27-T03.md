# E27-T03 · Models: manifest, favourites, custom models

## What it is

Each provider instance offers a list of models. The Models section of a provider lets a user decide which of them appear in the model picker: mark favourites (shown first), hide models, show or hide all, reorder, filter, and add **custom models** (a model id the provider accepts but does not list, such as a new release or a router's model name) with their own option definitions. The server builds the list from a **model manifest** (a JSON file bundled with the server and refreshed from GitHub) and from each provider's live model list.

## When it is used

- A new model ships before E6 Code knows about it; the user adds it under Models → Add custom model.
- A user with many OpenCode or Cursor models hides the ones they never use so the picker stays short.
- A user routes Claude through OpenRouter and adds the router's model ids.
- A user stars the two models they switch between.

## How it works today

- **Entry points:** Settings → Providers → instance → Models; the model picker in the composer reads the result (E15-T01).
- **Models section:** models grouped with favourites first; filter field; per-model star (favourite), enable/hide switch, move up/down; bulk show/hide ("Disable all"); capability tags per model; "Add custom model" opens an inline editor (slug, display name, per-model option definitions such as choices or toggles, and "copy options from a built-in model").
- **Storage:** favourites, hidden models and order are **client** settings (`providerModelPreferences`, `favorites`), so they differ per device; custom models are **server** settings inside the provider instance config.
- **Server catalog** (report 06 F-30): `model-manifest.json` (about 22 KB, version 1, `updatedAt`) bundled with the server and refreshed from `raw.githubusercontent.com/emikael/e6code/main/…` (TTL 1 h, retry gap 5 min, 10 s timeout); precedence remote > last good disk copy > bundle, newer `updatedAt` wins. It carries presentation, capability profiles (effort and context options) and legacy classification. Per provider: Claude's built-in catalog (12 models) comes entirely from the manifest with per-model `claudeCode` profiles (effort map, model suffixes, context-window tokens) and CLI-version compatibility; Antigravity uses the manifest (3 `gemini-3.8-flash-*` variants); Codex lists live via app-server `model/list` with the manifest as overlay; Cursor via ACP `cursor/list_available_models`; Grok via `initialize._meta` and `grok models`; OpenCode via its SDK provider list.
- **Behaviour to preserve:**
  - Custom models are not supported for Antigravity (docs).
  - Custom model ids appear in the picker with their declared options; "copy options" seeds them from a built-in model.
  - Hidden models never disappear from threads already using them.
  - The manifest fetch failing or offline falls back to the last good disk copy, then the bundle.
  - Claude models incompatible with the installed CLI version are marked or hidden per the manifest.
  - Mobile reads the same model lists for its pickers but has no Models settings (mobile "Refresh models" lives in thread settings).
- **Surfaces:** web, desktop, server.
- **Where the code lives:** web `components/settings/ProviderModelsSection.tsx` (641 lines), `CustomModelEditor.tsx` (387), `customModelEditor.logic.ts`, `modelSelection.ts`; server `apps/server/src/provider/ModelManifest.ts`, `ClaudeModelCatalog.ts`, `ClaudeModelManifest.ts`, `model-manifest.json`, `codexModelOptions.ts`; `packages/contracts/src/model.ts`; `docs/internals/model-manifest.md`.

## Problems today

- Preferences are split: favourites and hidden models are per device, custom models per environment, so a user's picker differs between laptop and phone.
- The model list is not virtualised; OpenCode and Cursor can list many models.
- The runtime fetch of the manifest from GitHub `main` is a behaviour to keep or drop consciously (report 06).

## Remodel goals

- **Experience:** the Models section is a quiet table: name, id in mono, capability tags, star and visibility; drag to reorder with keyboard alternatives. Custom model creation is a small form with validation and a preview of how the model will look in the picker.
- **Motion:** reorder uses the `layout` preset in the viewport only; drag follows the pointer 1:1; star uses `iconSwap` with the fill weight.
- **Performance:** virtualised list (E01-T20) above about 50 models; filtering is instant.
